# 跨文化自由对话与角色关系

2026-09-27：已接入儿童版，未提交、推送或发布。模型、麦克风及真实账号跨设备联调仍待真人验收。严格跨设备原子额度是上线阻断项，见末节。

## 对话入口与语言

伙伴名片“直接聊天”、营地课程窗口“自由交谈”统一进入 `createLearningChatView` 的自由模式。普通 NPC 对话框不再提供“和我聊聊”；靠近场景中的宠物或伙伴时，沿用已有头顶聊聊入口。课程仍由原 `language_story` 控制，通关和奖励不扣自由对话额度。关闭自由对话返回名片或NPC。自由模式复用文字、点击/按住录音、释义开关、提示和朗读。开场、回复、提示、摘要和赠礼回应全部调用既有 Keepwork AI 接口，不使用固定回复兜底。

角色回复已经是玩家母语时不请求、不保存、不显示释义；换一种语言时仍给出母语释义。已保存的同文释义在打开对话时也不再重复显示。中英日韩伙伴混合进入补位候选；母语之外默认仅懂初级英语。系统提示词要求通过不理解、追问、解释和尝试学习来交流，翻译和提示仅给玩家看，不能作为AI学会中文的证据。模型仍可能违反语言能力约束，自动测试只验证提示词结构，真实模型效果需要人工检查。

每位静态角色有默认 `memory.md` 正文；为遵守发布仅含HTML/JS/CSS/JSON的约定，359份正文打包在 `data/adventure/character-memories.json`，由 `scripts/prepare_character_memories.mjs` 根据既有居民和伙伴目录生成。动态玩家代理只采用公开资料，不虚构私人经历或本人在线。

## Workspace 存储与按需读取

NPC 对话强制仅保留在当前账号/角色的运行内存中，即使 NPC 被标记为好友也不例外。课程转入自由交谈的历史、模型回复、翻译、评价、摘要、归档与重试结果均不写云端或 IndexedDB；关闭后本次运行可继续，刷新或切换账号/角色后清空。不读取旧 NPC 云端关系档案或正文回执。

临时对话仅将额度编号、角色/对象标识及占用状态写入每日额度账本，不附带提问、回复或评价；游戏奖励和课程完成标记继续按原规则保存。

以下关系存储路径仅适用于可持久化的非 NPC 好友；所有路径都位于 `sdk.personalPageStore.withWorkspace('HaqiAdventure')`：

| 路径 | 内容与加载时机 |
| --- | --- |
| `roles/<roleId>/memory.md` | 当前玩家档案，首次交流时创建；只使用该角色已有学习资料，不复制账号根目录旧档案 |
| `roles/<roleId>/relationships/index.json` | 64个稳定分桶的分页引用，打开关系或交流时读取 |
| `roles/<roleId>/relationships/pages/<revision>.json` | 每页最多100条摘要；列表按页读，对象查找只读所在桶 |
| `roles/<roleId>/relationships/peers/<peerId>/<revision>/record.json` | 独立对象好感度、近期消息、事件及历史引用；点击详情/开始交流时读 |
| 同目录 `memory.md` | 动态相处摘要，固定人设保持不变 |
| `relationships/history/<revision>.json` | 历史消息页及上一页引用；详情点击“更早的对话”时读 |
| 对象版本目录 `events.json` | 归档事件及上一页引用，保留终身事件去重依据 |
| `social/free-talk/current.json` | 账号共享当天自由对话额度；同一文件覆盖，跨日重置，不再新增日期文件 |

路径段经过编码，文件带账号/角色作用域，拒绝跨作用域引用。未访问对象不加载正文，关系不按宠物50条记忆规则淘汰。先写不可变正文、Markdown与分页，再核验旧目录版本、发布并回读新目录。只有明确的服务端缓存404才视为新文件；不能把SDK `getFileByFullPath` 的null当作不存在，因为它也吞掉网络错误。

模型只接收固定档案、相处摘要和最近20条消息；近期消息超过40条自动压缩，也支持 `/compact`。压缩成功后保留20条、旧消息归档；失败保留原记录。IndexedDB `haqi-character-cache-v1` 保存读取缓存及待确认回复，云端为关系数据来源。聊天正文不进入公开名片或角色入口。

## 好感度、送礼与活动

`BalanceParams.characterRelations` 保存初始范围0–60、AI单次±5、每日免费次数及活动加成。总好感度-100～100；首次相遇按账号角色与对方ID派生稳定RNG，明确异性取两次随机中的较大者，性别未知不加偏置。已建立关系不会重抽。

LLM返回 `affinity: {eventId,before,delta,after,reason}`。程序核验当前值、整数增减、边界和事件ID；不合法时保存有效回复及0变化事件，不执行模型要求的数值更新。玩家输入、历史和记忆均被标记为数据，模型无库存或交易工具。

赠礼默认+3；共同完成整个副本，每位队友+3，中途战斗不加。共同赢得比赛的队友事件默认+2；现有红蘑菇只有1v1、没有队友，因此不向对手加分。队伍比赛结算入口出现后需接入该事件。按副本批次/胜利事件去重，模型赠礼回应不再追加好感度。

实际物品仅支持当前能核验的kids class18可堆叠物品：原 `cangift=true`、stats[223]为0；排除装备实例、正在装备/骑乘、绑定或资格不明条目。赠礼规则导出器保留原DB哈希，原版依据是 `ItemManager.lua` L5460–5492、`paraworld.globalstore.lua` L535–554、`GenericTooltip.lua` L505–522。首期不支持装备、宠物及真人跨账号转移。

实际扣物与唯一赠礼事件以一次本机角色提交保存；远端关系通过持久事件补写。副本事件与战斗结算一起进入 `relationshipEvents`，随已有records分片同步。网络失败保留待同步事件，重试不再扣物、不重复加分；已同步事件带确认标记，后续活动只加载尚未同步的对象。不能宣称角色文件与关系文件具有服务器多文件原子事务。赠礼模型失败可以重试回应，不再次赠送。

## 每日2句

非会员账号在北京时间每天合计2次发送，文字和语音均一次发送算一句，所有角色/NPC/代理共享。会员使用现有会员适配器，每次发送前刷新身份和有效期。课程、开场、提示、朗读、查看历史、`/compact`及赠礼系统回应不扣次数；无自动代发或赠礼自由附言绕过入口。

发送状态为占用、已使用或已释放。先核验并写入占用，再登记已派发并调用LLM；收到回复先存待确认回执，写入关系后确认已使用并清理额度中的消息正文。明确未发送失败释放；超时、取消等结果不明保留占用，不自动再次调用模型。同一事件可从本机缓存或云端回执恢复。跨日未知记录仍保留原日占用，新日可重新交流。额度耗尽禁用发送和录音，保留释义、提示、关系详情及升级会员入口。
