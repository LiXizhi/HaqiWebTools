# 照片生成专属头部

2026-10-07：按用户后续要求开放本地源码中的生成入口，并完善最终 WebP 自动上传。浏览器隔离验收使用模拟账号/生成服务/CDN与合成输入，不能视作真实账号线上生成验收。未提交、推送或发布。

## 用户流程与权益

创建角色与装备面板的「修改名字和形象」复用 `createHeroPicker` 的「用我的照片生成」。相机默认前置、离开取图或关闭窗口释放轨道；拒绝授权仍可上传。支持JPEG/PNG/WebP，原文件上限10,000,000字节。先在浏览器纠正方向，再拖动、缩放、旋转90°及方形裁剪。重新编码JPEG去掉元数据，输入照片尺寸最多512×512、JPEG质量0.90至0.70，严格不超过300,000字节，超限报错。

原照与压缩照仅在内存中，以data URI直接交给生成API，不上传公开图床、不写本机或云端存档、日志。照片会发送给AI服务，页面不承诺未经核实的服务端留存期限。仅卡通结果上传永久Keepwork CDN，用户可以在世界/好友资料中看到它。

每账号最多保留10个形象，会员同样受保留上限约束；满额时先删除不需要的历史形象，不自动淘汰。**照片生成形象为会员专属**，不再提供免费体验次数；当前有效 Keepwork 会员不限次数，一次运行一个任务。生成调用启用 SDK `stream` 与 `onProgress(receivedBytes)`，界面按120秒展示预计生成进度，注明通常需要90–120秒；结果返回前最多显示99%，不再根据流数据间隔显示等待或检查网络提示。上传阶段继续显示实际百分比。会员到期后保留已有形象。仅切换自定义头像及调整连接点免费；改名、身体、性别和收费预设沿用原规则。战斗中不能换装。

## 双参考图和脖子连接

通过已有SDK `aiGenerators.genImage` / `keepwork-image-pro` 调用，禁止自动改用用户自带密钥直连。第一张图仅供长相，第二张为身体类型对应的`elf-boy`/`elf-girl`布局参考。参考图片使用清单既有永久CDN并检查SHA-256、尺寸；缺少参考不调用生成。运行时清单`data/adventure/hero-art.json`与制作清单`data/hero-preview.json`保持既有模板一致。

输出4×4，行优先，0/4/8/12分别前/左/后/右，其余方向每格22.5°。提示词带完整逐帧`crop/neck/height`，要求只替换长相、不重新构图、不居中、不画肩膀、不复制精灵耳。不同方向脖子坐标各不相同，按原模板逐格继承。纯白背景或已有透明背景均可处理。

针对实际生成中出现的衣领、发辫齐切和写实脸，提示词将第二张参考明确为结构与美术风格底稿，第一张照片仅提供身份特征。每格仅允许完整头部，完全不含脖子（包括短脖子、颈根与后颈），明确排除所有衣服、领口、肩胸及背面衣领；长发以自然弯曲、向内收束的Q版完整发尾适配格内空间，不沿格边截断，也不靠移动颈部或整体缩头补救。强调大眼睛、简化鼻口、成组发束、柔和手绘明暗，排除照片滤镜、半写实、写实3D、皮肤毛孔与摄影级发丝。提示词检查不等于模型必然遵守，下一次真实生成仍须检查上述质量；已有图集不会自动重绘。

`photo_head_pixels_core.js`参考MagicHaqi的`petSheetWorker.js`：每格采样边缘背景并做连通区域去底、轻度边缘软化。禁用自动居中、强制格边擦除和主体平移。不会全图清除白色；封闭在轮廓内的白发、眼白和牙齿保留。白发与背景连成一片仍可能误删，属于必须真人验收的质量边界。透明格跳过重复去底。

像素处理在原生模块Worker中完成，压缩复用pet导出工具的Canvas WebP方式，严格不超过200,000字节。先尝试浏览器最高保真质量，超限降低质量再等比缩小；Canvas没有无损编码开关，quality=1不标作无损。原生Worker/OffscreenCanvas或WebP编码不支持时明确失败，不静默保存PNG。缩放同步作用于裁剪框、颈部坐标和头部尺度。

生成后的最后一步为「校准」，使用正式HeroRenderer与真实身体，默认朝前走路，不自动转向。点击前、左、后、右检查四向，另有逐格转头和回正按钮。直接拖动头部，或点击上下左右按钮调整连接位置，不要求输入坐标数字；每次调整作用于当前头方向所属的一排四格，保留各格原有连接点差异，不移动图集像素。支持恢复模板、单独保存；点击「使用这个形象」也会先保存未保存的校准，失败时保留窗口。保存不重新生成、不扣次数。同一头像不同已保存版本在渲染器中隔离，防止修改一位角色影响另一位。去底强度从最近一次生成原图重算；换设备或已经生成了下一张后，旧图原稿可能不在本机，只允许调整衔接。

## 存储、恢复和接口

`customHead`是可选、白名单化的资源描述：version/id/owner/gender/name/cdn/sha256/bytes/width/height/directionCount/frames。角色仍使用`headId`，自定义编号为`photo-<uuid>-boy|girl`。保存校验、云端投影、同屏战斗及社交名片透传描述；未知或不可用资源回退预设，不删除引用。头像登记在独立运行时目录，不加入公共预设和NPC随机池。

账号个人空间`HaqiAdventure`新增：

| 路径 | 内容 |
|---|---|
| `appearance/photo-heads/index.json` | version:2、owner、freeUsed、heads（最多10条正面预览摘要）、pending、lastCompleted |
| `appearance/photo-heads/heads/<headId>.json` | 一个形象一个当前文件：资源与16帧元数据，校准覆盖同一文件 |

每条摘要包含id/gender/path/createdAt/preview，以及可选的上次使用`appearance`/`bodyId`；preview是从最终WebP第0帧裁出的96×96透明WebP data URI，最多16,000字节，尊重正面帧mirrorX。DIY目录只读取index与内嵌小图，不请求所有图集和逐帧文件；点击正面头像继续编辑或点击「使用」后，才加载该形象文件与资源。实际游戏继续直接使用角色已保存的customHead，无需启动或逐帧读取历史库。窗口重新打开不自动选择最近生成结果。

历史卡片不显示名字和日期，只显示正面头像；右上角叉删除。点击头像进入校准步时，按摘要记录的上次男女/服装恢复预览（无记录则用生成时的gender），并立刻注册拟合头像供预览加载；沿用已保存连接位置，须再次完成四向确认后点「使用这个形象」才写回角色并关闭窗口，同时把本次男女与服装写回摘要；不重新生图、不扣次数。新生成结果同样先完成四向校准。编辑正面镜像后同步更新缩略图。

通过现有saveWorkspaceFile等待Cache写入应答，顺序为头部文件、index；免费计次与目录引用同时写进index。同一任务幂等，失败复用AI结果与已上传URL。删除仅移除历史库引用并释放名额，不返还免费机会；已经被角色使用的customHead与CDN资源保留，避免损坏已穿戴形象。没有自动清除CDN资源或远端旧版本。

旧version:1分页目录只读取摘要迁入新目录，不批量读取头像文件。旧条目尚无预览时显示「选择后查看」，首次点选时为该形象补正面小图。若历史数据已有超过10条，保留旧记录供分页删除，不自动丢弃；清理至少于10条才允许新增。普通读取复用账号内存，身份变化清空缓存。只有明确的服务器Cache不存在应答才初始化新目录，网络错误不能重置额度。

IndexedDB `haqi-photo-heads-v1`使用独立账号键，仅保存最近任务和AI输出，不保存真人输入。关闭窗口后任务继续；页面刷新后收到过的结果可继续去底/上传/保存。尚未收到响应则显示中断，用户放弃后可手动重试，不自动重新生图。生成接口没有已确认的任务查询接口，因此这类手动重试可能产生新服务请求。已生成原稿留在本机用于去底调整，目录只引用压缩后公开图集。

同一客户端串行、防重复点击及账号/token校验不等于服务端强制额度：记录可被篡改，跨设备同时生成仍可能绕过。此边界已获产品确认。

## 验收与启用

配置`data/adventure/photo-head.json`现为`enabled:true`，保留停用维护开关，移除永久阻挡生成的静态 verification 标记，不虚构已完成的真人质量验收。已读取线上实际加载的 `keepworkSDK.core.iife.js?v=6524b8f78261`（HTTP 200），核对 genImage 将两张 data URI 原样送入 image 数组、支持禁止自动上传输出，以及 uploadUserCDNFile 的永久 CDN 接口。实际请求仍只发裁剪照与布局参考；服务拒绝时失败且不扣次，不降级公开上传原照。真实账号的后端接收、免费用户权益与真人图集质量尚未实测。

最终 WebP 在上传前再次检查 MIME、200,000 字节上限和 SHA-256，调用 `sdk.cloudDrive.uploadUserCDNFile(file,{key,filename,onProgress})`。key 为 `haqi/heads/<headId>-<sha256>.webp`，避免中断重试生成不同随机资源；最终 URL 必须来自永久 Keepwork 用户 CDN。随后下载验证 CORS、解码尺寸、字节数和哈希，成功后才保存目录/额度。上传失败重用原稿和 WebP；保存目录失败重用已上传 URL。界面显示真实上传百分比，其余阶段为不确定进度。

自动验证入口：`tests/battle_photo_head.test.mjs`、`tests/photo_head_io.test.mjs`、`scripts/check_photo_head.mjs`。浏览器验收页为`tests/fixtures/photo-head.html`，所有写入都在内存，正式像素处理和渲染照常执行；模拟验收不代表线上服务成功。

照片入口位于头像卡片下方的独立操作行。点击立即打开独立 popup（共享 DetailDialog），加载、失败重试和照片操作均在子窗口内完成；关闭只退出子窗口并恢复父窗口按钮焦点。

裁剪区支持单指/鼠标拖动、双指捏合和鼠标滚轮缩放，缩放范围与滑杆一致（1–3倍），围绕双指中点或鼠标位置保持图像位置，触点取消后可继续拖动。人头虚线由独立SVG覆盖层绘制，不进入压缩或生图输入。

步骤导航可点击切换：重新打开默认第1步；本次窗口内返回裁剪保留照片与调整，关闭窗口后原照释放，需重新选择。第2步在有照片时确认生成，无照片但有已保存形象时转到校准；第3步校准已有结果。切换步骤不会触发生图或扣次数，任务运行期间禁用导航。
