# 2026-09-20 NPL WebSocket protocol

## Scope

Added `js/npl_protocol.js` and focused tests. This is a transport framing module, not a completed character importer. It does not log in, parse or execute Lua, read inventories, or modify saves.

## Source evidence

Source root: `c:/lxzsrc/NPLRuntimeCpOld/NPLRuntime/ParaEngine/NPL/`.

- `NPLDispatcher.cpp`: Emscripten connects to `wss://<host>:<port>/nplwebsocket` and sends messages generated by `CNPLMsgOut_gen`.
- `EmscriptenWebSocket.h`: no required subprotocol; outgoing messages use binary WebSocket frames.
- `NPLMsgOut.cpp`: activation header `A <target>\n`; optional runtime state `(rest)` and debug `NPL/1.0`; blank line followed by byte length and `:` (plain) or `>` (compressed). `AddMsgBody` strips the surrounding `msg={` and `}`.
- `NPLMsgIn_parser.cpp`: length-delimited input, optional CRLF, compression indicated by `>`.

The JS module supports UTF-8 byte counts, fragmented/concatenated input, plain and zlib-compressed bodies, bounded buffering/decompression, and explicit rejection of unsupported frame methods. It returns Lua body text without evaluating it. Binary method 0xff and Lua data parsing are not implemented.

## REST client implementation

Added `js/npl_rest.js`: a narrow non-executing parser for `data=<Lua string>,seq=<integer>` JSON envelopes, bounded request nesting, escaped Lua request serialization, and a browser-compatible REST connection with injected WebSocket support. The connection permits one pending request, correlates sequence numbers, and closes on timeouts, malformed responses, or transport errors. No automatic reconnect or authentication retry is performed. Closing is idempotent, including error-event reentry.

- `node --test tests/npl_protocol.test.mjs`: 9 tests passed, covering live reply syntax, unsafe input rejection, request encoding, correlation, concurrent request rejection, timeout and closure.
- End-to-end `connectHaqiRest({ WebSocketClass: WebSocket })` with the development `ws` package successfully returned `{"ver":26,"srvtime":"23:41:03"}` from `request('Ping')` using normal DNS and TLS validation.
- Node's built-in WebSocket failed in this run; its error/close reentry exposed a cleanup defect that was fixed and regression-tested. The new connection module itself has not yet been exercised in a browser; earlier browser verification covered the raw protocol only.
- Confirmed OAuth client ID `1000003`, and registered read APIs `Items.GetMyBags` / `Items.GetItemsInBag`. Authorization, original-client real-name/play-eligibility handling, actual inventory responses, character mapping and UI confirmation remain unimplemented. No account credentials were used and no character saves were modified.

## Read-only original-character adapter

Added `js/haqi_original.js` with injected SDK, fetch and REST connection dependencies. It reads the original Keepwork profile endpoint, verifies real-name status and server time, obtains an OAuth code for client `1000003`, uses `Ping.ver` for `AuthUser`, and reads the authenticated NID's character and bags. It returns an in-memory field-whitelisted snapshot; auth response/session keys, OAuth codes and identity-document data are not included. It writes no saves and is not yet wired to the import button.

- Requests are at least 350 ms apart to avoid the original REST limiter. Partial read failure returns no snapshot. Cancellation, timeout and account-token changes close the connection; HTTP redirects are rejected.
- Current limitation: minor accounts are explicitly refused because their original play-time allowance has not been integrated. This is not complete parity with the original client and must not be presented as support for all accounts.
- `node --test tests/haqi_original.test.mjs tests/npl_protocol.test.mjs`: 14 tests passed using synthetic authentication and inventory responses. These do not establish that production OAuth CORS, the selected character API response, or bag enumeration work for a real account.
- Read-only JS-to-Lua status query on the shared original web client returned `IsAuthenticated=false`. No token, NID, identity document, or player inventory was read. Real-account verification is blocked pending the user logging in through the browser.
- Remaining: production authorization/read verification, item/level/school/deck conversion with unsupported-field reporting, preview and confirmation UI, independent role creation, desktop/mobile checks, and required project validation. Do not mark the import feature complete.
