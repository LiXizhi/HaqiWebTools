# 汉字互动页 CDN 发布

入口：[hanzi_index.html](./hanzi_index.html)。它列出本目录所有正式汉字故事的永久 CDN 地址；`obsoleted/` 不发布。当前正式页面：门、休、森、光、国。在线入口：<https://cdn.keepwork.com/keepwork/cdn/hanzi/hanzi_index.html>。

## 创作新的汉字故事

- **先定字与故事**：核对汉字读音、含义、部件和笔顺；区分真实字源与艺术化想象，不能把画面隐喻当作文字学事实。用一句话确定主题，再写出「引子 → 探索 → 变化 → 成字 → 亲手写字 → 余韵」的分镜。每一幕让孩子看到或亲手完成一个变化，不要只播放长动画或堆砌百科文字。页面标题、拼音、提示及结尾应与这个字一致，文案简短、自然。
- **2D 范例**：[hanzi_guang.html](./hanzi_guang.html) 用 Canvas 2D 做整屏场景：观察暗处到火光的明暗转场、配色、文字与画面的节奏、进度提示和笔画描写。适合光影、平面绘本、笔墨及视差构图；借鉴其镜头语言与互动节奏，不要机械替换画面中的字。
- **3D 范例**：[hanzi_sen.html](./hanzi_sen.html) 用 Three.js 绘制有空间纵深的树林，并以 2D 墨迹层和标题/字幕承接叙事。适合空间、景深与镜头移动确实服务于故事的字；保留 WebGL 不可用时可用的 2D 画面，不为追求 3D 而牺牲清晰度或性能。所用 Three.js ES module 来自已核验的 Keepwork CDN，新增依赖须遵守项目 CDN 规则。
- **画面标准**：每个字有自己的主色、光源、构图与可辨识的视觉意象；从开场静帧到收束画面都要精致，主体清楚、字形转场可信。让场景中的物件和动作自然引出字的结构，而不是在最后突然贴上一个字。留足字幕可读空间，兼顾桌面与手机竖屏、安全区域、触控目标和高像素密度；避免高频闪烁，并尊重系统减少动态效果设置。
- **宽屏与竖屏完整呈现**：所有场景、镜头运动、字形变化、描写动画和交互步骤都必须在宽屏与竖屏上完整可见且可操作，不得让主角、笔画、提示、按钮或触控目标被裁切、遮挡或移出视口。按视口重新计算布局、镜头边界与命中区域，切换横竖屏后仍能继续当前故事；不能只缩放桌面画面或只检查开场静帧。
- **互动标准**：至少有一个推动故事的操作（例如点击点火、拖动、长按生长或描写笔画），立即给出可见反馈；提供清晰的中文操作提示、可重试/重播入口，必要时给出示范，让用户不会卡在某一幕。触控与鼠标均可完成；按钮支持键盘焦点和操作。处理拖动取消、窗口失焦、重播中断等状态，声音须在用户操作后启动且可静音，不依赖声音传达唯一线索。
- **验收**：本地 HTTP 服务打开页面，实际走通从开场到结尾及重播，并检查绘制/描字、无声音模式、移动端竖屏、桌面宽屏、缩放、减少动态效果及 3D 的 WebGL 失败回退；检查控制台错误和所需 CDN 资源。不要以仅能加载首屏作为完成标准。

## 新增或更新一个汉字并发布

1. 在本目录编写独立的 `hanzi_<拼音>.html`，遵循上面的创作要求，尽量内联样式与脚本。若依赖其他文件，先核对它们在 CDN 的实际地址并单独上传；不要把本目录的其他开发文件直接整目录上传。用现有的本地 HTTP 静态服务打开并验证交互。
2. 在 [hanzi_index.html](./hanzi_index.html) 的 `<nav class="list">` 中加入或更新一条链接。链接使用 `https://cdn.keepwork.com/keepwork/cdn/hanzi/hanzi_<拼音>.html`；删除或下线故事时同步删除入口。保持列表覆盖所有正式 `hanzi_*.html`（索引自身除外）。
3. 使用仓库已登记的 `upload-deploy-cdn-files` 技能及七牛脚本，从 HaqiCombatSim 根目录执行以下命令；先上传改动的故事，确认成功后最后上传索引：

```powershell
node C:\lxzsrc\keepworksdk\scripts\qiniuUploadLocalFiles.mjs --prefix keepwork/cdn/hanzi/ .\hanzi\hanzi_xiu.html
node C:\lxzsrc\keepworksdk\scripts\qiniuUploadLocalFiles.mjs --prefix keepwork/cdn/hanzi/ .\hanzi\hanzi_index.html
```

将 `hanzi_xiu.html` 换成新增/修改的文件名；批量更新时可在同一次调用中列出多个明确文件路径，但不要重传无关页面。脚本读取现有 `qiniu.yaml` 凭据并提交 CDN 刷新；不要提交凭据，也不要运行项目根目录的 `npm run upload`（它发布的是整个游戏）。示例使用已安装依赖的 Node 兜底脚本；也可使用技能目录中的 Python `qiniu_upload_local_files.py`，参数一致。如果缺少依赖，按技能说明处理；不要把任何密钥写进命令或仓库。

4. 核对上传输出中每个文件的成功记录及刷新结果，再访问实际 CDN 页面与索引，逐项点击新链接验证内容和交互。索引必须最后发布，避免先露出未上传的链接。覆盖同名 URL 后如仍看到旧内容，等缓存刷新生效后再核对。

## URL 规则

前缀固定为 `keepwork/cdn/hanzi/`，文件名即 URL 最后一段。独立文件模式下脚本不会自动带上本地 `hanzi/` 目录，所以必须显式使用此 `--prefix`，不可省略。`hanzi_sen.html` 依赖已登记的 Keepwork CDN Three.js 模块，其余现有正式页使用内联资源；如后续引入相对路径资源，必须同时发布并验证依赖。CDN 不会自动发现新文件：每次新增故事都需编辑并重新上传索引。
