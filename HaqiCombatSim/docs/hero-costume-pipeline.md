# 固定基础图集的批量换装流水线

2026-09-27 用户纠正：目标是一次批量生成不同服装，而不是在某套服装上反复重画动作。此前将服装成品、失败样张继续作为生成参考的流程废止。单张站立图也不能取代完整动作基准。

## 基础动作与换装分开

男角色先用 `assets/hero-preview/male-walk-cycle.webp` 作为位置与比例尺，生成独立的 `assets/hero-preview/male-walk-ref.webp`。后续只在这个 reference 上优化动作，所有男装独立参考它；不再直接参考原服装图集。女角色暂以 `assets/hero-preview/female-walk-cycle.webp` 为固定基准。先检查基础图集四方向走路和站立、脖子位置、比例及裁剪，再记录验收版本和 SHA-256。文件存在不代表动作已验收；当前批次配置未声明基础动作已通过。

基础图集为 7 列 4 行，前六列走路、末列站立；四行分别正面、左侧、右侧、背面。动作问题在基础图集阶段统一修正，不在每套服装中分别发明动作。修改基础图集后另建版本，后续批次一致使用新版本。

## 每套服装独立生成

运行 `python scripts/plan_hero_costume_batch.py` 从现有服装设计定义生成 `art-references/body-variants/fixed-base-batch.json`。现有定义中的历史长提示词不作为新请求使用；只读取服装设计。每条请求显式记录基础图路径及哈希，所有同一性别请求引用同一基础图。各请求可独立执行，一套服装对应一次完整图集生成。

提示词仅要求换服装、保留全部动作、位置和比例。服装轮廓可以不同，不强制恢复原披风轮廓。禁止把 male2/male9 等服装成品、之前失败的样张作为下一套的动作参考。某套不合格时调整该套设计描述，从同一基础图重新生成。

## 登记和验证

生成时记录实际传入的参考图哈希、设计、提示词和原始输出。打包脚本用于对齐的基础图，不等于 AI 实际收到的参考图；不能用前者替代生成来源证明。历史 provenance 不追溯改写成新流程。

检查服装一致性、基础动作是否保留、脖子定位、透明边缘及格子裁剪。每张运行时 WebP 不超过 200KB，上传后核验 SHA-256 与 CORS，再更新游戏清单。使用已有 CDN 流程，仅上传 CDN，不复制到 Git 镜像；不自动提交或推送。
