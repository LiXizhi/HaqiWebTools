## 我的魔法卡包：卡包页签栏多出一条竖滚动条（用户截图 + 红箭头）

- 现象：`我的魔法卡包` 里「基础卡包」页签和「购买卡包」按钮之间出现竖滚动条。
- 根因：`css/adventure.css` `.bag-tabs{overflow:auto}`（页签栏自己是滚动容器）+ `.bag-tab{height:52px}` 固定高。按钮内文字/画布比 52px 高出 1–4px 时（字体、缩放差异），按钮 overflow 可见，溢出部分会算进祖先滚动容器的可滚动区域 → 页签栏出现竖向滚动条。本地字体恰好不高出，所以之前没复现。
- 改动：`.bag-tabs` → `overflow:visible;flex-wrap:wrap`；`.bag-tab` → `height:52px` 改 `min-height:52px;max-height:84px;overflow:hidden;line-height:1.25`。卡包多时换行，焦点描边不再被裁剪。
- 复现/验证方法（可复用）：`tests/fixtures/deck.html` 里 loadResources 会挂（要拉 CDN 图集），所以自建最小页：动态 import `view_adventure_deck.js` 的 `renderDeckEditor` + `view_adventure.js` 的 `el/button`，只 fetch `data/adventure/{chapter,combat}.json`，给一个桩 assets（`effects.cards:{}`、空 `draw`/`skillArt`），自己拼 `.overlay>section.modal.wide>.modal-body`，就得到与真实面板同布局的 DOM；再用 Edge `--headless=new --dump-dom` 把测量结果塞进 `<pre id="probe">` 读出来。注意 `view_adventure.js` 依赖 `view_adventure_settings.js`，后者若 `tr` 从 `./locale.js` 导入会整图报错（`tr` 在 `locale_runtime.js`）。
- 另：本仓库当前有并行会话在改 `adventure.css`（宠物食槽/设置页签）、`docs/devlog/devlog_2026-09-28.md`、`view_adventure_settings.js`，改同一文件时注意对方可能用旧缓冲覆盖。

## 新建角色的默认外观改为随机（2026-09-28）

- 需求：`Haqi.html` 新建角色第 1 步「起名字」里男主角/女主角两张卡的头部与服装要随机（用户截图红箭头指向四处 ‹ › 箭头）；默认头不能是「黑人」。
- 「黑人」在数据里的落点 = `data/adventure/hero-art.json` 的 `heads` 中非洲肤色家族：`onyx-boy/onyx-girl`（rich deep brown skin）、`cocoa-boy/cocoa-girl`（medium warm brown skin）。判断依据在 `art-references/hero-head-variants.json` 每个变体 prompt 尾部的肤色描述（`jade/amber`=东亚浅肤、`sun/copper`=欧洲、`indigo`=南亚、`wave`=拉美，都不算）。
- 实现：`js/hero_body_core.js` 新增 `DEFAULT_HEAD_EXCLUDE=/^(?:onyx|cocoa)-/`、`randomHeroHeadId()`、`createHeroDraft(manifest,seed)`；`js/adventure_app.js` 的 `paintCreation()` 把原来的字面量草稿换成 `createHeroDraft(assets.hero?.manifest)`（`roleDraft` 每次进创建页都会被清空 → 每次新建都重新随机）。`createHeroPicker` 自身没动，仍是确定性的（`tests/hero_picker.test.mjs` 依赖它在无记忆时落到第 0 套）。
- 关键约束：**衣服不能跨性别混搭**。`hero_renderer.js` 用 `appearance.gender` 选 `male-walk`/`female-walk` 骨架（两套帧裁剪/几何不同），且 `bodyVariant(gender,id)` 对性别不符的 bodyId 返回 null → 会静默回落到基础身体，跨性别衣服根本不显示。`validHeroBodyId` 也强制 bodyId 前缀与性别一致。所以「衣服男女随机」只能实现为各性别内部 14 套随机。
- 验证手段：`node -e` 直接 import `hero_body_core.js` + 一份 `document` 桩复刻测试里的 `node()`，跑 200/80 次抽样断言确定性、默认头不含 onyx/cocoa、`createHeroPicker` 不回退到第 0 套。测试用例加在 `tests/hero_picker.test.mjs` 第 5 项。
- 环境坑（再次确认）：agent shell 里 `curl http://127.0.0.1:<port>` 一律 `code=000`（netstat 能看到 LISTENING，但连不上），所以本地起 `python -m http.server` 做浏览器验收这条路在本环境不通；`file://` 又因为 ES module + fetch 走不了。要视觉验收只能在用户自己的浏览器里打开。
- 手动验收页 `tests/fixtures/hero-creation.html` 已同步改用 `createHeroDraft`，`?seed=<数字>` 可固定复现同一套外观。
