# 大岛探索与分区制作

2026-09-20。营地和五座主岛均已拆成独立布局源文件与运行时 JSON。五主岛参考原版俯视地图分别扩建，支持岛内导览、道路行走与区域天气；专属原版剧情仍待导入。

## 已实现的哈奇岛

- 5600×4400 世界坐标，旧版为1800×1600，矩形面积约8.56倍。角色尺寸和210单位/秒的步行速度不变，不通过放大角色或画面冒充扩大地图。
- 八个导览区域：北部雪山、西部密林、金色山谷、河畔田野、南部湖畔、哈奇小镇、东部海滨、南岸沙滩。导览名称为网页版概括性命名，不声称是原版正式地名。
- 参考原图的雪山在北、森林和田野在西、小镇在东南、游乐区在东、河流分隔区域的关系。是二维空间改编，不是从原版3D地形自动转换，也不是逐像素复刻。
- 3位既有居民移入小镇，另在旅行入口复用法斯特船长，2处既有怪物分散到林间与湖岸支路。安全主路、回环与桥梁连接各区域；不新增虚构任务、奖励、采集或怪物掉落。
- “世界地图”入口中的“当前地图”显示地形与当前位置，选择目的地后沿路步行；仍可随时用既有手动移动操作改变路线。路牌可查看简短环境描述，顶部显示当前区域。全局六岛传送地图保持原入口。
- 北部高地采用烘焙的地表等高线，森林、草地、雪地、沙滩采用不同地表与树种。建筑、树冠和人物继续复用现有永久CDN图集。

## 统一编辑与生成入口

| 内容 | 应编辑的文件 | 作用 |
| --- | --- | --- |
| 共享视觉与生成规则 | `config/maps/generator.json` | 道路宽度/边缘色、森林密度/间距/树种、地表、雪山、降雪/沙尘/灰烬/薄雾、桥梁 |
| 每岛空间设计 | `config/maps/islands/<id>.json` | 尺寸、海岸、区域、道路节点、河湖、山体、入口、居民和遭遇位置 |
| 实际运行数据 | `data/adventure/maps/<id>.json` | 自动生成的树木、道路、桥梁、地标及已合并地域规则；不要直接编辑 |
| 地图目录 | `data/adventure/maps/index.json` | 六岛尺寸、出生点和文件路径；同步写入 chapter.json.worldMapIndex |
| 生成器 | `scripts/generate_island_maps.mjs` | 调用纯规则生成器，检查关键地点和道路双向可通行后输出 JSON |

在项目目录运行：

```sh
npm run generate:maps
npm run check:maps
```

`npm run build` 自动执行一致性检查：源文件调整后忘记重新生成会拒绝构建。`npm run export:adventure` 在重导章节后自动重生成地图。确定性种子保存在各岛文件；相同源文件生成相同结果，sourceHash 用于追溯。生成器在浏览器之外运行，玩家进入岛屿时不再随机布树。

例如：调整 `roads.width` 改所有主岛主路宽度；调整 `forest.spacing` 和 `biomes.forest.forest.density` 改树间距及森林密度；调整 `biomes.snow.weather.count/speed/wind` 改雪量与飘落速度。`biomes.snow.mountain` 是雪山层级配色，`mountain` 是统一山体形状参数。`themes.fire/ice/desert/dark` 集中保存岛屿主题差异。优先级为共享规则 → 岛屿引用的 theme → 岛内 overrides；营地保留较窄道路和低树木预算。单一区域可覆盖自己的 weather/forest，因此覆盖过的字段不会随全局同字段改变。

岛内 `routes` 是坐标折线，主路与支路可形成回环；`rivers`/`lakes` 的 material 可选 water、ice、lava、dark。生成器为道路与河流交叉点生成沿道路方向的桥，碰撞与画面共用旋转几何；湖泊必须绕行。哈奇岛保留已手工设置的桥。区域名为网页版概括性名称，地图是参考原图空间关系的二维改编，并非原版3D地形精确转换。

六岛法斯特船长与旅行入口均先打开世界地图，选岛后再主动传送。所有当前地图导览使用同一生成数据。普通世界地图入口默认当前地图，顶部可切换世界地图，船长默认世界地图。其他四岛当前只有复用船长和环境地标，没有伪造新的剧情、怪物或奖励。

天气只根据玩家所在区域选择种类。粒子按世界坐标漂移，镜头跟随角色时留在原地，走出屏幕后才从另一侧补入；同时仍只绘制最多64个，不按岛屿面积增加。开启系统“减少动态效果”后停用。雪树积雪、山体、地表使用原生 Canvas 与已有图集，不增加依赖或图片下载。

## 性能实现

`adventure_large_terrain.js` 将静态地面按512世界单位分块绘制，缓存上限24张。每块含2像素边缘余量，Canvas为516×516；像素存储约24.4MiB，加宽560、高度按各岛宽高比计算的导览图（最大约1.15MiB）。这是Canvas像素估算，不代表浏览器总内存或GPU实际分配。

超宽屏或缩小时，若可见块数超过预算，使用较低地面分辨率的1024等尺寸世界块，位图仍为516×516。防止可见块不断被缓存淘汰。每帧最多补绘两张冷块，其余暂时用低分辨率导览底图覆盖，随后数帧逐步清晰；不出现未加载的黑洞。普通帧复用缓存，不重画地表纹理、道路、河岸或树影。首次进入新区仍有生成和贴图上传成本，不承诺所有设备零卡顿。

树木、建筑、居民、怪物和路牌按256单位空间桶索引，先按视野查询再排序，树冠继续按脚底Y值遮挡角色。碰撞也查询局部对象。数百棵树不需要每帧全量排序；数量以布局种子和当前几何生成结果为准。

长距离寻路优先使用验证过可通行的道路图，首次建立后按world实例缓存；道路接入失败才回退原有网格寻路。河流、湖泊不可穿越，桥梁开放通行。纯规则仍在 `*_core.js`，不依赖浏览器，也不消费战斗随机数。

## 存档兼容

v2存档使用 `worldLayoutVersion:2`。缺少字段的旧哈奇岛存档先按旧尺寸校验，再一次性移到新小镇出生点；上一版哈奇岛大地图（布局版本1）和营地位置保留。布局版本0/1的其他四岛迁移到对应新入口。新版坐标按章节地图索引中的各岛尺寸校验。已有任务、装备、战斗决定和奖励账本不重置；战斗退出/失败返回所属岛出生点。未知未来地图版本拒绝读取。

任务追踪使用生成后的world居民位置，避免走向旧章节快照中的坐标。章节内 `originalPosition` 与Lua/XML来源保持原样。

## 后续岛屿与美术制作流程

1. **参考校验**：原版俯视地图定大方向；进一步读取对应 `WorldData/*.NPC.xml`、`*.Arenas_Mobs.xml` 和任务源，才填写原版专名、居民、战斗与剧情关系。仅凭图像不能推定完整剧情。
2. **空间骨架**：为每岛独立定义海岸、区域中心、道路、河流/湖泊、桥梁、居民、遭遇点与入口。当前六岛源文件位于 `config/maps/islands/`；生成后的同一份几何直接供地面、碰撞、导览与寻路共用。
3. **探索节奏**：先设计可辨识的地标、分岔、回环和安静路段，再增加遭遇。以现有步速，2100单位约10秒。建议主地标之间保留8–15秒步行，支路30–60秒可回主路；这是后续关卡设计起点，不是已实现的硬限制。
4. **分层生成**：生成共享可平铺草地/雪地/砂地纹理、道路边缘、岩壁/树木/建筑透明图集，以及少量独特地标插图。不要生成一张5600×4400包含全部人物和文字的岛图。固定俯视角、脚底锚点、人物比例、光照方向与调色板；复用已有场景截图作为风格参考。
5. **拼接与碰撞**：先固定路口、桥头和邻接边界，再制作各区地表；不让模型自行改变路口位置。模型生成地表可以分区预烘焙，但桥梁、交互对象、前景树冠独立成层；道路和水域碰撞由同一几何数据驱动。
6. **资源准备**：按Maisi美术技能处理WebP、alpha、裁剪、来源与哈希，每张运行时WebP≤200,000字节；上传验证永久Keepwork CDN后写入资源清单。只加载当前区域与邻区所需独特资源；共享图集只加载一次。当前程序地表版只增加地图 JSON，不新增美术下载。
7. **剧情装配**：按稳定的岛/区域/居民/任务ID关联内容，不把故事烙进底图。先安全抵达，再介绍地标，接着允许支路探索和遭遇，最后用回环返回；奖励仍经过既有任务与战斗结算。
8. **验收**：所有入口、居民、路牌、怪物与回程点可达；路径实际行走不穿树、不穿水、不堵桥；旧存档可恢复；低分辨率地面无接缝；桌面与手机可移动和导览；测量冷块生成与热帧，不只测静态截图。

当前还没有完整原版城堡、游乐设施、各岛专属地标美术与新剧情，未提供持久探索迷雾或发现奖励。下一步可逐区替换地表和地标资产，保留已经跑通的空间与存档规则。

隔离预览：`tests/fixtures/exploration.html?island=ice&assets=local`，`island` 可选六岛 ID，默认 town。该页使用内存中的50级测试角色，不读写玩家存档；去掉 assets 参数检查默认CDN资源。正常游戏仍遵守等级限制。该验收页不进入发布构建。

场景测试页现支持顶部岛屿、区域、天气选择和缩放；自然积雪树及天气图集详见 [场景素材](environment-art.md)。
