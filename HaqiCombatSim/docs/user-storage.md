
## 2026-09-30：单客户端内存读取与 Cache 直接写入

按用户确认的单客户端写入模式，登录读取服务器最新目录；后续角色入口、已加载分片和宠物文件以内存为准，未加载文件首次使用才读。保存不再查询远端版本或读取历史判断远端分支。主动刷新角色目录和重新登录会重新读取；账号/token 变化使旧请求失效。本地未同步进度与登录快照不同仍保留备份选择，避免直接丢弃本地数据。

所有游戏文件写入集中于 `keepwork_file_io.js`，继续使用 `personalPageStore.withWorkspace('HaqiAdventure')` 的 Cache 接口：`savePageData(path,'content',text,true,true,{directWrite:true})`。新增 SDK option 默认关闭，仅游戏调用启用；跳过 SDK 文件预读和合并，不安排后台同步，等待 pageCache PUT 明确成功，不再写后 GET。支持 `.json` 与 `.md` 完整内容，不改变原文件格式或其他 SDK 用户的默认行为。SDK 能力标志未就绪时沿用旧 Cache 暂存/同步接口，不绕开 SDK；旧 CDN 包仍可能有 SDK 内部预读，新选项上线后才消除这部分请求。

成功后更新内存入口和文件缓存；失败、超时或身份变化不标记角色已同步。写入顺序仍是分文件、历史、入口；同客户端角色保存和 SDK 同路径直接写入串行。不可变分片成功后可复用，重试不重复上传已经确认的文件。关系正文、历史及每日额度首次读取后复用内存；SDK 没有新增远端 CAS。

社交关闭后台轮询，岛屿入口读取名单，邮件在打开时读取，公开名片复用内存并在主动刷新时失效；内容未变化不重复发布。会员普通查询合并请求并复用账号内存，手动刷新、充值和账号事件更新状态。角色目录按角色进一步拆分加载尚未在本轮实现；当前登录仍加载既有角色必要分片。


# 用户存储结构（2026-09-25）

## 宠物独立文件与有限记忆计划（2026-09-27）

**已接入正式儿童版，待用户效果验收，未发布。** 已实现独立实例、场景互动、分享口粮、出生领养、逐只分文件与正文按需加载；Keepwork适配器已做模拟验证，实际账号远端读写仍需登录验收。 [宠物互动与繁育计划](pet-interactions.md)已按用户新要求改为每只宠物独立文件：`roles/<roleId>/pets/<instanceId>/<revision>.json`，包含其成长、卡包、冷却及最多 10 条长期记忆。居民和伙伴的随行宠不单独建文件。普通相遇只留在本机。

角色入口仅保留分页索引根引用；宠物索引每页最多100条摘要与实例引用，分页摘要记录主人和出生地图。云端只保存主角自己的宠物和待领养宝宝。居民、伙伴的随行宠不单独建文件。进入场景只加载实际需要的自己的宠物和当前地图宝宝，不遍历加载全部收藏，也不递归加载记忆对象。普通相遇写在本机 IndexedDB，亲密度提升才写入自己宠物的长期记忆，每只最多 10 条。详情、互动和战斗按需补齐。未加载不能被当作不存在或空关系写回。实例及索引页只按变化写入，出生／领养先核验全部新文件后统一发布入口。宝宝领养沿用原实例身份，亲缘和出生去重不受遗忘影响。

旧收藏一次性迁移可读取全量；日常只在 `save.pets` 中组装已加载正文，未加载对象由摘要／文件引用表示，完整导出／备份才显式遍历所有实例。血量、饥饿、临时位置与护理计时仍在本机；印记和冷却截止为持久玩法记录。不可变历史版本沿用原保留规则，不自动清理。正式角色已使用这一分层；下文旧收藏表中的宠物正文已进一步拆分，不再跟随物品收藏全量读写。

## 原则

游戏使用 `AdventureSave` 保存当前状态；宠物部分由轻量目录与按需正文组成。IO 层负责拆分和组装，不改变战斗公式。物品、宠物收藏与当前战斗配置分开；临时数值只保存在本机 IndexedDB。云端始终使用 Keepwork server pageCache，只有核心状态变化才写入。

## Personal workspace

前缀：`<username>/edunotes/store/HaqiAdventure/`。入口版本为 `schemaVersion: 2`。

| 文件 | 内容 | 更新条件 |
|---|---|---|
| `roles/index.json` | 账号当前角色 ID、各角色小型当前状态及分文件引用、云端版本 | 核心状态或当前角色改变 |
| `roles/<roleId>/items/<revision>.json` | 已知物品编号清单、宠物收藏与成长、装备实例及强化/宝石、拥有的卡牌 | 新增/移除物品类型、宠物成长、装备实例属性变化 |
| `roles/<roleId>/battle/<revision>.json` | 物品数量账本（含货币/口粮）、当前装备及 GUID、坐骑、卡组、主角阵位、出战宠物阵容；复制当前装备实例与最多四只出战宠物的持久属性 | 物品数量、换装、换坐骑、换卡组、调整阵容/位置，或当前战斗物品/宠物成长 |
| `roles/<roleId>/records/<revision>.json` | 购买流水、战斗奖励去重记录、钓鱼纪录、学习档案 | 对应历史/纪录改变 |
| `roles/history/<revision>.json` | 小型入口快照及父版本引用，不再复制整个收藏和历史内容 | 核心状态成功同步前 |
| `checkpoints/<time>_<uuid>.json` | 用户主动保存的完整核心状态快照，不含临时数值 | 手动保存；战斗结束后才允许 |
| `memory.md` | 既有独立学习档案接口 | 当前主应用尚未调用同步入口 |

`revision` 后缀是不可变版本：只有变化的分文件才新增版本，其余引用原文件。先写入、核验分文件，再发布小型入口，避免中途失败造成装备/收藏版本混杂。历史版本保留用于冲突与回溯，不自动删除。

目前没有真实充值订单流水接口；已有 `transactions` 是商城购买流水，已移出 index。账号 `magicBeanExchange.exchangedUntil` 仅是防止重复兑换的单个日期水位，仍属于当前账号状态，不是充值历史。

物品收藏不是绝对不变：新物品类型、强化装备、宠物升级必须保存；已有物品数量账本放在小型战斗背包中，所以增加货币或消耗口粮不会连带重写所有宠物。单纯换装、换坐骑、切换出战宠物和阵位也不会重写整个收藏。战斗背包是持久属性副本，加载时核对其与收藏一致，不复制当前血量或饥饿值。

## 本机 IndexedDB

数据库 `haqi-role-runtime-v1`，object store `roles`。键包含账号/访客身份及角色 UUID。

- 主角当前血量，宠物当前血量、饥饿值。
- 恢复/饥饿计时、护理提示记录。
- 当前坐标、朝向、钓鱼与副本共用的精力（含本地日历日补满标记）。
- 签到当日在线时长；已领取及 VIP 领取标记仍在核心存档中。
- 未结束战斗的种子、初始条件和决定序列，供本机重演恢复。

写入合并为约 250ms 一批；内存中的同步接口保持不变，启动先准备 IndexedDB，再验证/打开角色。运行状态绑定角色存档版本及地图，旧版本战斗不会覆盖已结算的新状态。数据缺失或浏览器清理后，主角按满血、宠物按满血/满饥饿恢复，精力按玩法默认满格；在线时长从零计、位置回当前区域出生点，不恢复已丢失的本地战斗。

本地核心副本继续使用 `haqi.roles.v1.guest` / `haqi.roles.v1.account.<username>` 的 localStorage 键，内部以 `localFormat:2` 标记，移除临时字段。显式导出/恢复前备份仍可包含完整本机存档。

## 请求时机与迁移

- 访客不读取 workspace。恢复账号时读取 index，并读取所引用的分文件；不可变分文件在当前会话缓存，后续同步检查不重复下载未变化的收藏/记录。
- 仅血量、饥饿、位置、在线计时、临时 revision 或最近游玩时间变化，不标记云端 dirty；重复选择同一角色也不触发同步。
- 未结束战斗只在本机持久化，结算或撤退后再同步物品消耗和奖励，避免云端恢复半场战斗。
- 每次核心同步仍核对云端版本，保留账号切换和跨设备冲突保护；没有核心变化时不新增历史或分文件。
- 旧版全量 `roles/index.json` 仍可读取。下一次核心同步时迁移到分文件；旧文件/历史不删除。旧版云端中的未结束战斗先迁入本机，结算后发布新格式。
- 钓鱼纪录由角色 `records` 分文件保存，新版不再维护重复的 `fishing/records.json`；旧镜像留存但不作为恢复源。

## 2026-09-30：启动时角色存档恢复

启动和账号切换使用 `prepareOpen/open` 的 `recover:true` 路径，逐个准备资源并校验角色。无法读取的角色不进入可玩列表，也不再使整个标题页失败；其余角色仍可选择，没有可用角色时可新建。直接登录在恢复模式下停留角色选择。

打开恢复模式不写存储；首次选择或创建角色时，将原目录原始文本（或旧单角色原始文本）一起保留在本机 `recoveryBackup`，后续写入继续保留。宠物分文件不删除，旧战斗等运行时继续留在原角色的 IndexedDB 键，不复制到 localStorage 或云端。写入失败时不替换内存目录和原始目录。恢复备份按访客/账号隔离，严格导入及云端校验不放宽。

恢复模式不自动用部分目录覆盖云端，也不自动用云端覆盖本地备份；界面明确提示仅本机保存并暂停云端同步。云端读取失败时允许使用本地角色或新建本地角色；主动刷新成功后沿用原有冲突检查。当前不提供备份角色的自动修复或合并入口，兼容性修复后的备份恢复需另行处理。真正缺少基础游戏资源时仍需重新加载，但不展示存档异常堆栈或开发命令。
