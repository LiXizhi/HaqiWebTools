## 2026-09-30 补充：仅已确认好友可长期记录好感

此规则覆盖下文“其他主人互动即可长期结算”的描述。仅真实账号且已确认双向好友关系，才允许人物关系与宠物关系持久化；发送申请、组队、聊天、赠礼均不等于成为好友。AI/NPC没有加好友入口，因此其关系只作临时累计。

非好友的人物好感、对话关系与宠物印记仅存在内存：人物关系在同一账号/角色会话内可继续累计，刷新、退出或切换账号/角色清除；宠物临时关系还会在离开当前场景时清除。陌生人头顶打招呼仍只播放动画，不增加任何好感。有效对白、通关及其他互动可增加临时好感，界面标明“临时”。临时宠物印记不触发繁育，不能混入自己宠物文件。成为好友后，从之后的有效互动开始长期记录，不把临时历史自动补写。

聊天额度核验与赠礼物品消耗继续按原规则记账，但额度回执剔除非好友好感数据，非好友关系不进入本机待同步缓存、关系文件或角色活动流水。组队结算只返回关系事件，由应用根据实时好友名单分别路由。结算时再次检查好友状态，不能仅凭动作发起时的资格。

旧实现以物种为收藏键；现在收藏与阵容使用实例ID，繁育领养可增加同种实例，重复捕获仍沿用原规则。四阶段为幼年1–9级、青年10–24级、成年25–39级、隐藏形态40–50级。独立个体、性别、关系与待领养状态均已接入。

## 二、场景互动与好友印记

### 场景身份与表现

- 每位参与玩法的 NPC 配置固定宠物实例身份、物种、性别和等级。刷新、离开场景或 NPC 再次出现均复用原身份，不重新抽取。
- 主角使用实际拥有的随行宠物；仅供展示、未进入收藏的默认陪伴外观不作为可繁育个体。
- 主角宠物与其他宠物普通靠近可以追逐、贴贴、跳舞，只播放表现，不增加好友印记。
- 主人完成有效互动后，双方宠物靠近贴贴或跳舞，播放爱心动画并结算印记。
- 有效主人互动仅包括主角与 NPC 完成一轮对白。NPC之间的交谈不会触发宠物互动、印记或繁育。仅打开窗口、路过或站在一起不算。
- 宠物社交不显示头顶文字或聊天气泡，不依赖在线 AI 服务；只显示短暂动作、印记和特效。

### 印记与关系条

- 配对以两个宠物的独立实例身份组成无序键，同一对不会因先后顺序不同重复建档。
- 按北京时间划分日期，同一对每天最多获得一枚印记；对白与投喂共用该上限。
- **累计三枚即可达到繁育进度，不要求连续三天。** 例如第一、第三、第五天分别获得印记，第五天即可满足印记条件。此规则取代最初提出的“连续三天”。
- 分开保存该段关系的历史好友印记总数与未用于繁育的可用印记。关系仍在记忆中时持续累计，出生仅扣除三枚可用印记；遗忘后按下节规则结束该段关系，不无限保留全体旧关系。
- 未成年、同性、冷却中的宠物仍可累计；分开或漏一天本身不清空印记，容量淘汰按下节执行。
- 互动时在两只宠物头顶短暂展示同一配对的三格好感进度，超过三枚时显示满格并保留实际余量；不叠加状态文字或聊天气泡；距离超出互动范围、离场或展示到期即隐藏。详细状态仅在背包详情／验收面板查看。
- 页面隐藏不补算互动；时间倒退不回退已保存的日期水位，也不重新开放已结算日期的印记。

### 每只自己的宠物记住最近 10 只（2026-09-30）

长期记忆只写在主角自己的宠物上，最多 10 条，按最近一次亲密度提升时间保留。居民或伙伴的随行宠不再单独占一份宠物文件，也不保存它们的记忆。不保存对方完整宠物数据。同一对象以实例ID去重；同一主人的宠物不计入这套跨主人好友玩法。

普通靠近只记在本机 IndexedDB 的 `petMeetings` 里，同样最多 10 只，不进入云端宠物文件，也不增加好友印记。只有亲密度提升（当日新印记）或因此出生宝宝时，才更新自己宠物文件里的长期记忆。自己的宠物靠近这最多 10 只已有好感的宠物时，双方头顶显示粉色圆点。

每条摘要只保存对方实例ID／主人ID、最近确认的等级、最近有效互动时间、共同关系代次、历史与可用印记、最后结算日期和关系版本。不给每枚印记追加流水，不保存全部聊天正文或动作历史。等级使用最近实际见到并校验的等级。容量 10 写在 BalanceParams 的 `memoryCapacity`。

1. 长期记忆最多 10 条，按最近一次亲密度提升时间从新到旧保留，超出的最旧一条让位。这是上限，不再因为近 7 天而暂时超过 10 条。
2. 只有主人对白或主动投喂带来当日新印记时，才把对方写入长期记忆。同一天再次对白或投喂不改宠物文件。普通靠近只更新本机相遇记录。
3. 对方没有单独存档。自己的宠物还记得这段关系时，继续沿用原代次和印记，不因为对方文件不存在就从零开始。
4. 双方都保存了记忆但代次不一致时，仍视为新关系。代次取双方序号生成。当日已经结算过的日期不能靠重新认识再领一次印记。
5. 时间倒退不降低已记录时间。裁剪发生在有效互动时；结果没变就不写文件。

双方如果都是会保存的宠物，记忆仍可以各自裁剪。有效互动只把变化写回自己的宠物。不批量加载被淘汰对象。

遗忘不影响宠物自身等级、性别、繁育冷却、出生序号、父母身份及已经出生的宝宝。亲缘是每只宝宝固定的两个父母引用，不是永久社交记忆；不递归保存族谱。此有限记忆规则取代前版“所有配对历史永久累计”的无限保留语义。

### 主动投喂与聚餐

- 主动投喂自己的随行宠物，播放放下口粮、附近宠物走来分享的动画。
- 复用营养餐，每次消耗一份；满饱食时仍可主动分享，按钮明确提示消耗。
- 只恢复被投喂宠物的饱食；来访者不额外得到食物、经验或饱食奖励。
- 被投喂者与每只实际到场的宠物分别结算印记；来访者之间不会因此互加。重复投喂仍受每对每天一枚上限约束。
- 自动进食不触发聚餐或印记；没有到场宠物时，本次投喂仍按正常消耗和饱食规则完成。
- 有效到场由控制层根据场景状态确认，视图只展示结果；不能依赖动画完成回调发放印记。

## 三、繁育、宝宝与领养

### 出生条件与冷却

同一配对必须同时满足：异性、双方实际等级达到成年阶段（当前25级）、至少三枚可用印记、双方不在冷却中、双方在同一场景再次靠近且当前不在战斗中。

选择幼年外观不影响成年资格。仍在双方记忆中的未成年印记保留，成年后再次相遇即可检查。领取第三枚印记时双方已经靠近，也可在同一有效场景事件中检查出生条件。

每次出生一只，扣除该配对三枚可用印记，并为父母各自设置出生时刻起 **72小时** 冷却。双方在冷却内不能与任何对象繁育，历史好友印记不清空；冷却期间仍可积累印记。离线时间可使冷却到期，但不离线自动生产，必须再次相遇才结算。

多个配对同时满足时，优先本次互动对象，其余按稳定配对键排序。每次结算后立即以更新后的冷却检查下一对，避免同一宠物同时生多胎。

### 随机生成规则

- 从359种目录中筛选出系别属于父母任意一方的全部物种，再按物种等概率抽取；不是先平分两系概率再抽物种。
- 同系父母只能生同系宝宝；异系只能生两者系别之一，不突破父母系别范围。候选为空时不扣印记、不设置冷却，明确报告配置问题。
- 宝宝性别以等概率继承父母一方。
- 初始等级1、经验0、使用该物种初始卡包，不继承父母等级、经验或卡包。
- 使用 `rng_core.js` 的独立玩法随机流，出生种子及结果持久化，刷新不能重抽，也不影响战斗随机序列。
- 使用该物种幼年图集，按正常尺寸的 **0.5倍** 展示；领养后幼年阶段保持该比例，10级进入青年阶段后恢复普通阶段尺寸。

### 待领养与领取

- 出生位置选择父母附近可行走点，宝宝标注“待领养”，点击直接领养。
- 未领养宝宝随角色保存；刷新、离岛、父母离场不删除，重返出生地图时恢复展示。
- 领养后从场景移除，加入战宠背包，不自动替换现有阵容。
- 允许同种多只，每只独立保存身份、性别、成长、亲缘、卡包及冷却。
- 出生结果、印记扣除和父母冷却作为一个核心保存操作；领养标记与背包新增作为另一个核心保存操作。持久化成功后再发布新的内存状态及成功提示。
- 存储失败不移除宝宝；出生和领养均使用稳定记录身份去重，重复点击、刷新和重试不得重复领取。
- 首期属于当前角色单人世界，NPC之间不产生新宝宝；已有待领养宝宝记录仍保留，不引入真人争抢或共享世界服务。

### 状态流

普通靠近 → 玩耍（无印记）；主人有效互动／主动投喂 → 每日配对去重 → 印记增加 → 检查成年、性别、冷却与同场靠近 → 持久化出生 → 父母冷却＋场景待领养 → 点击领养并持久化 → 独立个体进入背包。

不满足繁育条件时保留玩伴关系与可用印记，直到发生容量淘汰。冷却到期只解除资格限制，不自行产生宝宝。

## 四、实现与接口边界

### 纯规则与场景层

新增宠物互动纯规则模块，提供处理有效互动、增加印记、检查出生、生成宝宝和领养宝宝的能力。输入为经过控制层确认的宠物身份、场景事件、注入时间、配置和种子；输出为候选状态与展示事件。纯模块不访问 DOM、网络或存储。

控制层负责有效对白、到场判定、出生顺序和既有保存流程；视图负责寻路表现、贴贴、跳舞、爱心、关系条和宝宝点击区。用现有图集和 Canvas 绘制／位移实现，减少动态效果时用静态爱心和印记反馈。窗口继续复用共享关闭按钮，手机宝宝命中区域不能随半尺寸图像一起缩到难以点击。

互动距离、聚餐范围、印记门槛、冷却、宝宝比例和动画频率全部走 BalanceParams。NPC配置明确记录稳定身份、物种、性别、等级及所属主人，不能从每次场景渲染临时推导新身份。

### 多个体与兼容

- 收藏和阵容引用改为实例 ID；物种 ID 只查询定义。同一实例不能重复上阵，同种不同实例可分别编队。
- 旧宠物保留已有身份、经验、卡包、外观偏好，稳定补齐性别；迁移带版本标记，多次读档不能再次生成。
- 既有捕获、购买、任务发放保留原重复处理语义，本期仅繁育领养必定创建新个体。新增同种实例后，旧重复奖励仍作用于原有收藏个体；没有旧个体时使用最早领养的同种个体，稳定顺序以实例 ID 兜底。
- 进行中的旧战斗先按原检查点重演并结束，再迁移收藏和阵容引用；不能改变旧战斗结果。
- 宠物详情、编队、喂食、卡包、战斗快照、导入导出与家园联动格式均需审计物种键假设。格式扩展须版本化，不能用旧的一种一只校验静默丢弃新个体。

### 每只宠物独立文件与按需加载（2026-09-27已接入）

**每只宠物独立保存，取代前版“收藏包含全部宠物＋统一关系分片”的方案。** 同一物种的不同实例也分别保存；主角、NPC及待领养宝宝均使用稳定实例身份。下述路径是应用文件布局，不是新服务端接口。

| 数据 | 保存位置与变化时机 |
| --- | --- |
| 单只宠物的身份、物种、性别、亲缘、成长、卡包、繁育冷却及有限关系记忆 | `roles/<roleId>/pets/<instanceId>/<revision>.json`，只写发生变化的实例 |
| 宠物列表摘要与实例文件引用 | 分页宠物索引，只含实例ID、物种、名字、等级、归属／领养状态及文件引用，不含记忆和卡包正文 |
| 当前地图的NPC宠物、待领养宝宝引用及出生锚点 | 正式存档通过分页摘要的归属与地图字段筛选；锚点只在所需宝宝正文中读取。独立仓库另有地图索引，正式入口不重复维护一套 |
| 当前阵容及出战所需属性 | 既有战斗分片，保存实例引用与最小战斗快照，不复制关系记忆 |
| 出生身份、父母身份、生成结果、出生序号及领养状态 | 宝宝自身文件；父母各自文件保存单调出生序号与冷却，避免无限追加出生流水 |
| 动画、临时位置、寻路、血量及饥饿 | 本机运行层，按实例隔离，不标记云端核心 dirty |

每只宠物只有一个当前有效实例文件；沿用不可变 revision 保留历史版本，不能误解为每次覆盖同一路径。角色小型入口只保存分页索引根引用，不直接塞入所有实例列表；索引固定每页最多100条，修改实例只更新对应索引页及必要的根引用。历史修订按现有存储规则保留，本方案限制活跃实例和记忆大小，不宣称历史版本数量永远不增长。

加载和写入契约：

- 进入场景只读取该场景实际需要的宠物正文；只出现一只时只读这一只，不为记忆对象递归拉取文件，即使近期记忆暂时超额。物种图集等静态目录继续共享。
- 两只宠物互动时按需取得双方文件；背包浏览先读当前页摘要，打开详情才加载所选实例，切换阵容／进入战斗只补齐参与的实例。其他地图的宝宝不随启动加载。
- 尚未加载与不存在必须区分；加载失败允许重试，不能当作空宠物、空记忆或零印记后覆盖保存。
- 同一实例请求合并，缓存按账号、角色、实例及revision隔离。离场可释放不再使用的干净正文；有未保存变化的实例完成保存后再释放。
- 不再在启动或普通同步时组装所有宠物的完整 `save.pets`。需要适配当前 `splitRoleSave`、`joinRoleSave`、全体护理、收藏校验与dirty比较，不能只拆云端文件却在启动重新全部下载。
- 非出场宠物的恢复按既有本机时间规则延后到实际使用时结算；不得为了定时护理遍历加载全部云端实例。全量导出／手动完整备份可显式逐页读取全部实例，普通游玩不走此路径。
- 单只升级只保存该实例及关联摘要；配对印记变更只保存双方实例。战斗快照仅在相应出战持久属性变化时更新，不因关系变化重写战斗数据。

出生事务保存双方父母、宝宝文件及所在地图／宠物索引；领养事务保存宝宝归属、收藏索引与场景索引。先写入并核验所有新revision，再发布同一个角色入口，沿用账号隔离、版本冲突及 Keepwork cache API 核验；失败不得发布一半状态。宝宝领养后沿用原实例ID和文件，不另造一份宝宝。

旧收藏迁移属于一次性全量读取例外：拆成实例文件，生成分页摘要与地图引用，核验完成后才切换入口；旧数据保留，失败不切换。恢复旧战斗仍先完成旧版重演。懒加载后的核心校验只覆盖已引用且本次需要的实例，修改未加载实例前必须先加载并校验它。

印记和冷却截止仍是持久玩法记录。冲突时不能把两个版本的印记或宝宝简单相加；同一出生身份与领养状态用于重试去重，不依赖动画回调，也不宣称服务端防改时钟或防存档回滚。

### 互动站位避让（2026-09-27）
宠物先寻路到主人旁边的可行走空地，再播放互动；候选位置避开主角、NPC 和其他场景人物。双方到位后才结算，找不到空地不回退到主人脚下。人物进入保留位置时取消互动并收起特效。BalanceParams 统一配置站位偏移 140、横向避让 78、纵向避让 135 和到位容差 12（世界坐标单位）。

睡眠表现修订：挂机与战斗倒下均使用对应成长阶段图集第四列的睡眠图，保持正常宽高比例，不叠加 ZZZ，不通过压扁站立图模拟睡觉。
