# 潮汐、浮岸与风帆岛

2026-10-06 接入网页原创续篇，仅使用儿童版内容。三个等级章节可以独立开始，顺读时组成「没有送到的回答」：一封没送出的信、地图上被擦掉的名字、庆典里被剪掉的求救声，最终指向同一段回航。

| 岛屿 | 等级 | 主线 | 场景与副本 |
| --- | --- | --- | --- |
| 潮汐岛 `tide` | 60 | [灯还亮着](story/chapters/C870000.md)：两只杯子、同名的收信人和两种记日方式；父女重逢，但不替岑宁决定原谅 | 灯塔、信街、船坞、潮洞；两处秘境和60层回声试炼塔 |
| 浮岸岛 `float` | 70 | [两张图都是真的](story/chapters/C870100.md)：不同路线、被删去的旧港、父亲的救船记录与未还的桥费；共同重画地图 | 测量台、井边旧账、瀑布旧路；两处秘境和80层回声试炼塔 |
| 风帆岛 `sail` | 80 | [庆典前的求救](story/chapters/C870200.md)：反挂的红帆、白补丁、岸上名单；前两岛的信和港名最终接上 | 风车、归帆厅、帆厅、档案室；两处秘境和100层回声试炼塔 |

每岛12个任务、4名居民、4种野外遭遇、6个地标、6处建筑摆放和三条往返道路。地图为4800×4800，居民、道路、怪物领地和出生点由固定配置与种子生成。秘境分别为单人3场、双人5场；试炼塔使用现有编队、逐层记录及每十层奖励，奖励与学习反馈均沿用已有规则。塔可离开休息，不要求一次完成。怪物外观与法术使用已核验的儿童版模板；新怪物编号和等级、生命、经验、奇豆写在各岛配置中，未改变战斗公式。

现实世界互动使用既有现实地图面板。小禾、米拉、小舟各提供一次可选观察邀请，分别观察河岸与桥、不同走法、靠水城市及等待的人；玩家可以在地图里观察，也可与伙伴自由交谈。打开面板不移动冒险角色，不需要定位、登录、开麦或实地出行，跳过后仍能完成主线。母亲的现实港口经历属于本故事的虚构设定，不新增现实地点的事实资料或生产接口。

## 可替换配置

作者源是 `data/adventure/island-packs/`，生成的章节文档用于阅读和审阅，不作为回写源。

| 改什么 | 作者源与流程 |
| --- | --- |
| 岛名、等级、居民、任务对白/目标/奖励、怪物、秘境剧情/层数、伙伴容量 | `island-packs/<id>.json`；入口为 `index.json`。故事、NPC、战斗和副本分别安装进现有目录，不增加存档类型 |
| 海岸、道路、水域、地标、出生点、居民与怪物坐标、建筑摆放、地表颜色 | `config/maps/islands/<id>.json`；地图中的位置覆盖包内的默认位置，两处调整时保持一致。`encounterSpurs:false` 为野外怪物保留路旁领地，不自动铺路到怪物脚下 |
| 场景建筑裁剪、CDN、原图哈希 | `data/adventure/building-art.json`；浮岸/风帆码头复用潮汐图集的实际码头帧 |
| 群岛缩略图、群岛位置及尺寸 | `data/adventure/world-map-art.json`；三岛共享 `continuation` 透明图集，岛名标签沿用现有 DOM |
| 生成登记表与伙伴配置 | `node scripts/prepare_island_packs.mjs` 从包中生成 `js/island_pack_registry_core.js` 和 `social.json` 的扩展行；勿直接修改生成行 |
| 地图与内容来源索引 | `npm run generate:maps`，随后 `python scripts/export_story.py`；`--check` 可检查过期产物 |

`index.json` 的 `enabled` 用于发行时选择内容包；改变启用列表后重新生成地图和故事再构建。已有存档引用岛屿、任务、怪物和副本编号，因此已发行内容保持编号稳定；删除一个已使用的包需要先设计存档迁移，不能仅删文件。替换对白、外观、奖励或布局不需要另写玩法控制器。主线首任务只检查本岛等级，其余按本岛前置任务推进，没有其他岛的硬前置。

默认等级上限由已登记岛屿的最高推荐等级推导，本次为80；经验门槛沿用现有 BalanceParams 的 `xpGrowth` 扩展，原50级进度保留。后续数值覆盖仍走 BalanceParams。任务收获之外，进阶卡牌与装备通过现有学习、卡组和商城流程准备；60级并不意味着一级初始卡组自动变强。副本生命成长和塔奖励仍使用已有 `dungeonJourney` 参数。

浏览器 IO 读取内容包，纯核心安装器校验编号、任务动作、前置循环、怪物目标和副本来源；核心不访问 DOM、fetch 或存储。静态 HTTP 与 Vite 数据包都加载同一份 JSON。发布数据只包含配置与代码，四张美术图不打入 dist。

## 打磨记录

1. 按既有续篇提案建立人物关系与三条独立任务链；先检查两只杯子、两张地图和白补丁这些具体物件是否能串起前后线索。
2. 核对知情顺序，去掉副本入场时过早透露扣信人的信息；九份入场故事分别写出眼前目的、危险及退出路径。玩家发言保留现有三种学习奖励身份。
3. 将主线长段对白拆成短段，给接取和交付按钮写对应回应；让道歉、公开账目与庆典修订各自有结果，避免所有问题都靠打败守卫解决。主线战斗只清开路线，不能替代修桥、还钱或原谅。
4. 对照桌面/手机实际画面修正透明图、建筑位置和怪物道路间距，扩大地图到既有大岛面积范围；正式CDN逐图核对哈希、透明像素及Canvas跨域读取。新居民复用原有外观，但使用独立身份和故事编号。

新增中文内容沿用项目中文设计、既有多语言流程；未补译的文字会诚实回退中文，不承诺已经完成多语言配音或翻译。

## 美术提示词

群岛缩略图使用原有透明群岛图作为风格参考：明亮手绘魔法童话、俯视等距的实体海岛、干净透明背景，三岛横排且不重叠。潮汐岛以白石蓝顶灯塔、弯曲海岸与暖灯为主题；浮岸岛以阶梯高岸、瀑布、蓝金测量台和高低桥为主题；风帆岛以蓝金风帆塔、花园、风车和帆形建筑为主题。不要文字、标签、船只、UI、整块海面或背景阴影；保留与原岛一致的画笔、边缘和比例。

建筑原图为三行三列透明图集：第一行灯塔、蓝顶村屋、石木码头；第二行测量台、蓝金村屋、瀑布花园；第三行帆形塔、风车村屋、帆形花园。每个物件独立落地，边缘干净，不带环境背景与发光方框，适合原Canvas的Y排序。第二轮编辑清除物件间的背景光晕，保留原建筑细节与透明通道。

使用 `scripts/prepare_island_pack_art.py` 裁剪、缩放、保留透明通道并压缩到每图200,000字节以内。清单保留AI原图哈希与转换后WebP哈希、尺寸和裁剪。实际上传完成后填写永久Keepwork CDN地址，浏览器默认使用CDN，`?assets=local` 明确选择归档副本。

## 验证入口

- `npm run test:battle`：包含 `battle_island_packs.test.mjs` 的任务完整推进、奖励单次领取、旧进度、高等级战斗重演、道路领地、九副本与配置错误检测。
- `npm run check:maps`、`python scripts/export_story.py --check`；Python故事测试验证覆盖、作者源及稳定编号。
- `node scripts/check_island_packs.mjs --playwright <已安装Playwright包路径> --url <静态服务地址>`：隔离内存存档，验证CDN哈希/透明/CORS、桌面和手机六组场景/对话布局、九副本的真实按需加载与出入、真实接取按钮与现实地图回调。报告与截图输出至 `tmp/island-expansion/review/`。
- `scripts/check_island_performance.mjs` 可测三岛静止/移动的帧间隔；桌面模拟不代表实体手机性能。

具体通过数量与全量测试中现存失败见 [QA记录](qa-report.md)。本轮未执行网站发布、Git提交或推送。
