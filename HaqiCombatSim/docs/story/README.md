# 故事工作台

先读 [按等级排列的主线章节目录](story-master.md)，再读 [重编与续篇设计](story-design.md)、[中文简明样章](story-samples.md)。总稿是现有资料的事实整理，不是新编小说。样章与设计是未应用的创作稿。

`story-master.md` 只列章节目录，不再堆放正文。连续前置路径至少4个任务构成主线，正文与奖励放入 `chapters/C<首任务ID>.md`。孤立任务、短链和不属于任何4步路径的短分支放入 [NPC孤立任务与短支线](story-side-quests.md)，按接取NPC分组。

同一前置网络的长分支与汇合保留在同章；仅仅同时开放许多独立任务不算长链。首任务等级决定目录排序，未配置等级者置后；保留上限及后续条件，不修改实际解锁逻辑。

NPC双语交流、居民日常对白和招呼见 [NPC独立文档](story-npc-dialogues.md)；副本入场、试炼塔及原版过场见 [剧本独立文档](story-dungeon-scripts.md)。任务本身的NPC对白仍随任务留在章节或支线文件，不把人物发言一概移走。索引的 `document` 字段可按原编号找到当前文档。

## 按编号修改

例如：“把 S1203-L06 改得更容易跟读，保留邮差与守卫无法沟通、邀请玩家站在身边这两个事实。”

`S` 是永久场景编号，`L` 是场景内永久文字编号。它们不是任务ID，也不表示章节顺序。正文顺序可变，编号不变。每个编号只维护一份简单易懂的改写文字，不再选择难度档位。

1. 在 [索引](story-index.json) 找到编号，核对 `text`、`source.sha256`、说话人和阶段。
2. 对照索引顶层 `sources` 的文件哈希确认源码版本。源码已经变化，先重读并处理冲突。
3. `writable: true` 表示已有经过验证的JSON作者源字段；不是授权自动写入。`author` 指向应修改的位置，`source` 是展示快照。
4. `writable: false` 仍可编辑文稿，但不能自动回写。生成脚本的语义选择器需要人工核对；原版XML、历史场景和新创作需要另行接入。
5. 仅将文本修改形成审阅差异，不修改 `action`、任务条件、数量、奖励和学习事件身份。奖励摘要只读。
6. 替换作者源后走已有生成流程与测试。不要通过编辑生成JSON绕过作者源。

JSON定位采用JSON Pointer；原过场使用 `xml:Motion序号/MotionLine序号/Frame序号`，均从0开始。数组位置仅在该哈希版本内有效。上游结构变化不能拿旧位置直接写入。

## 重新整理

从项目根目录运行：

```powershell
python -X utf8 scripts/export_story.py
python -X utf8 scripts/export_story.py --check
python -X utf8 scripts/render_story_samples.py --check
python -X utf8 -m unittest discover -s tests -p "story_*test.py"
```

仅生成 `chapters/C*.md`、`story-side-quests.md`、`story-master.md`、`story-npc-dialogues.md`、`story-dungeon-scripts.md`、`story-history.md`、`story-index.json`、`story-registry.json`、`story-report.md`。不会修改游戏配置，不会覆盖本页、样章或设计稿。需要本机原版目录才能重新提取过场；现有产物可独立阅读。

不要删除编号登记表。停用场景及文字以 `active: false` 保留；新内容消耗新编号，不复用旧编号。插入及重排优先按同场景、说话人、阶段与原文字指纹保持编号；重复文字的移位若有歧义则分配新编号并报告，不猜测。上游同时重排并改写时仍须人工核对。

简明样章的人工作者源为 `sample-text.json`。修改后显式运行 `python -X utf8 scripts/render_story_samples.py` 更新展示稿；该命令会在来源槽位变化时拒绝渲染，要求先核对，不改变作者源或运行时配置。

## 阅读范围

- 主线目录：按入口等级列出章节，各章按任务前置顺序相邻展示当前内容与原版对白；原版参考不宣称已可玩。
- [NPC支线任务](story-side-quests.md)：孤立任务和短链按接取NPC归组，不打断主线。
- [NPC独立文档](story-npc-dialogues.md)：双语交流的中文稿、居民日常对白、原版招呼及停用NPC内容。
- [剧本独立文档](story-dungeon-scripts.md)：副本与试炼塔故事、非teen原版过场。
- [历史档案](story-history.md)：废除任务。
- [检查报告](story-report.md)：覆盖、过滤、来源与尚待核验的边界。

角色的称呼差异按各来源保留，例如章节介绍中的“苏苏／莫卡”和部分旧NPC姓名“茜茜／莫尼”。不能仅为统一行文就改动身份。原文引用奖励而与配置不一致时，以配置事实为执行依据，创作稿不得承诺额外发放。

原始素材含重复成长任务、限时付费任务与旧活动；这是资料现状，不代表推荐全部放入未来长篇主线。阅读体验整理与正式玩法调整是不同工作。

## 接续创作约定

新增正式场景先取得独立稳定ID，再编写正文；概念提案暂用“续卷一·第01章”等编辑标签，未接入时不冒用现有 `S` 编号。新角色、新地图、新任务只作为设计提案，不能倒写成原版事实。

本轮没有自动回写命令。未来回写器必须先产出逐编号差异、验证源哈希及白名单字段，遇到缺映射或歧义拒绝该项；不能将Markdown整页交给模型任意修改JSON。

## 平行章节扩展

新章节建议以首任务等级作为入口，后续通过任务前置推进；无需绑定上一章结尾。连续至少4个任务后，重新导出即可进入主线目录。章号由根任务ID生成，不随等级排序改变；前置重构造成章节拆并时须核对引用，S/L正文编号仍保持。

索引的 `questChapters` 保存章节、入口等级、任务次序及最长连续路径，`sideQuestIds` 保存支线归属。当前和原版场景随同一任务路由，不把一个任务计算两遍。废除任务不参与主线识别。
