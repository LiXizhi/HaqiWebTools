# 2026-09-17 · 卡包 / 配卡 / 决斗圆盘演示

## 需求（用户）

> 有个很重要的概念是卡包大小，配卡。并且每轮会随机从中抽 N 张，支持扔掉卡片。卡片用完就无法出卡了。
> 动画演示：可以在 2 队中间画个圆盘，上面几个点，中间可以显示下卡片，以及谁对谁使用的。各种 buff/debuff 效果显示清晰。

## 调研

- 抽牌 / 弃牌 / 打空引擎里已有（`ShuffleDeck` / `PrepareCard` / `DiscardCard` 1:1），但缺**卡包容量**：Lua 由卡包道具 `stats[167]`（总容量）`[170]`（单卡上限）`[171-177]`（分系单卡上限）在 `Arena.OnReponse_TryEnterCombat`（arena_server.lua L8011-8166）校验；teen 同 `spell_name` 共享单卡上限（L8119）。道具表（GlobalStore）不在本地。
- 客户端初始卡包：kids 14 / 单卡 3（CombatCardDeckSubPage.lua L38-40），teen 18 / 单卡 5（CombatCardManager.teen.lua L41-43）。
- 旧预设卡组固定「每卡 2 份、最多 40 张」，与容量无关。

## 实现

- 引擎：`global.deckCapacity` / `deckEachCapacity`（默认 40 / 6，用户确认正常玩家约 40 张、单卡 6）/ `deckPresetCopies`（官方卡组每卡份数，默认 3，用户强调带满不一定最好）；`clampDeck`（含 teen 同名共享、同 key 合并、`deckTrimmed`）；`deckCounts` / `isDeckExhausted` / `restoreDiscardedCard`；弃牌与出牌解耦；`pass.reason` 增加 `no_cards` / `deck_empty`；`totals.noCardPasses`；双方打空提前判平（`decksExhausted`）；`summarizeUnit` 增加 DOT/HOT 段值、冷却、卡包计数。
- 预设：`presetDeck` 改为轮询展开（A,B,C,A,B,C…），由 `createUnit` 按容量裁剪 → 小卡包仍保持卡种多样，容量改大自动填满。
- 批量：`noCardPassRate` / `deckExhaustedRate` / `deckDraws`；批量页可勾选「用对战页配卡」。
- UI：`utils.svg()`；对战页重写 —— 配卡面板、SVG 决斗圆盘（站位点 / 头像 / HP / 魔力点：普通蓝、超级金 + `n+m` 数字 + 图例；teen 无超级魔力点 / 卡包剩余 / 状态徽标）、中央卡牌面板 + 能量束 + 飘字、事件流分步动画（慢 / 正常 / 快 / 无 + 跳过）、弃牌模式与右键弃牌、卡包计数条、状态明细板；跨页切换接回对局（`game.ui`）。
- 测试 +4（34 例）。

## 数据观察

见 [qa-report.md](../qa-report.md) 2026-09-17 表：teen 18 张卡包下生命系 1v1 胜率 2%、平局 45%；不限容量时 27%。卡包容量与 HP / 伤害同级重要，结论前须确定目标玩家的真实卡包容量。
