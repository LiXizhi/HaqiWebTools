# 卡牌美术与施法演出制作流程

本流程适用于当前儿童版卡库。卡面背景、技能主体、程序粒子和音效分别制作，共用技能基础ID连接。新增图集预算为每张 **≤100,000字节**；五系背景 **<24,000字节**。等级/品质变体共享基础技能，不需要重复生成图片。

当前有225个基础技能、701条卡牌定义、18张共享主体图集及6张专属九帧图集。生成配置不等于战斗机制已支持；新增规则仍须依据Lua来源移植、测试，并更新未支持统计。

## 1. 给新技能建立制作单

复制 [制作单模板](templates/card-art-request.md)，填写：

- cardKey：数据里的实际卡牌键。不要从base名猜cardKey，部分基础技能只有低等级/品质变体。
- base：独立法术的稳定ID。等级、品质变化复用原base；不同法术不可仅按Level字样合并。
- 中文名称、学系、原始说明、单体/群体、友方/敌方、主效果和附加效果。
- 原版卡面/资源清单条目/来源哈希；没有原图的系统技能明确标注语义生成。
- 演出节奏：蓄力、释放、命中、余效；有无高费专属动作；希望出现的粒子和音色。

先核对 `data/kids/cards.json`、`data/kids/card_names.json`、`data/adventure/spell-effects.json` 与 `data/kids/spell-art.json`。原始数值由数据导出流程提供，不能为了画面把伤害/费用另写一份常量。`npm run prepare:effects` 使用显式type映射，不认识的类型应先补映射；执行前检查脚本是否会覆盖正在编辑的演出参数。

## 2. 选择图片方案

| 方案 | 用途 | 布局与复用 |
|---|---|---|
| 共享主体 | 普通攻击、护盾、治疗、陷阱等 | 3×3最多9种或4×4最多16种独立技能，每格一个主体 |
| 专属动作 | 有明确召唤物或标志性高费技能 | 独立3×3，九格为同一个主体的连续动作 |
| 卡牌背景 | 学系边框、卷轴、说明区 | 保持现有五张空白背景，标题/费用/说明不烘焙到图里 |

共享主体图的格子是不同技能，不能把整张图当作连续动作播放。专属动作要求外形、朝向、比例和脚底基准一致；不要逐帧紧裁剪，否则播放时会跳动。

新图集优先新ID（如 `fire-04`），避免重排已发布图集。修改旧图集必须一起更新所有受影响格号。专属动作使用 `hero-<稳定技能ID>`，不按费用值命名。

## 3. 用原画参考生成透明图集

使用内置imagegen，并遵循适用的imagegen/美术技能。先查看原图，准备带编号的参考联系图，编号顺序必须与计划的cells顺序一致。生成器只负责主体，法阵、抛物线、屏幕位置和动态文字由程序负责。

共享主体提示词模板：

```text
根据附带原版卡面中的中央技能形象，重绘游戏技能主体图集。
透明RGBA背景，正方形，严格4×4等分，从左到右、从上到下排列。
每格中央约60%区域放置一个完整主体，四周至少20%留白。
无文字、无编号、无卡框、无卷轴、无地面、无格线。
每个主体独立，不跨格；保留原画的主要形象、轮廓和学系配色。
小尺寸也应清晰，光晕克制，避免大面积半透明烟雾占满格子。
格子1：[base、名称、原画主体与颜色]
格子2：[…]
……
未使用格子保持透明。
```

专属动作提示词模板：

```text
参考附图主体，生成同一角色/技能的透明3×3九帧动作图集。
严格等分，无文字/卡框/编号/格线。所有格子保持相同镜头、比例、
中心轴和脚底基准，朝右。动作/武器/光效都不能触碰格边或跨格。
1显现，2蓄力，3稳定站姿，4预备攻击，5释放，6跟随动作，
7命中余效，8恢复，9消散。第三格同时用于静态卡牌。
攻击轨迹与远处目标不要画进图集，由运行时粒子负责。
```

生成后逐格查看，发现错序、重复、缺格、跨格、角色变形或假透明棋盘时先修订。打包器只能校验透明与几何，不能判断语义对错。当前24张最终提示词可参考 [skill-art-prompts.json](skill-art-prompts.json)。

## 4. 登记计划并压缩为WebP

在 `data/adventure/skill-art-plan.json` 的 `sheets` 末尾添加共享图集（放在所有hero条目前），字段结构参照已有条目：

```json
{
  "id": "fire-04",
  "columns": 3,
  "rows": 3,
  "cells": [{
    "base": "Fire_NewSpell",
    "name": "新法术",
    "kind": "meteor",
    "school": "fire",
    "original": {"system": true}
  }]
}
```

示例的system仅适用于确无原卡的系统技能；有原画时复制其完整来源条目（local、cdn、sha256、sourceEntry、sourceIcon等），不能只填一个临时URL。hero条目设置 `hero: true`、3×3，并在cells中引用已存在的base；当前打包器固定输出帧0–8，静态卡面使用第2号格（第三格）。

在本地临时目录，例如 `.asset-cache/new-skills/`，为本次生成的每张图写 `<id>.json`：

```json
{
  "source": "C:/本机生成目录/new-sheet.png",
  "prompt": "本次实际使用的完整最终提示词"
}
```

```powershell
python scripts/prepare_skill_art.py .asset-cache/new-skills --reuse-existing
```

`--reuse-existing` 从已提交清单和WebP复用没有新PNG的旧图集，并核验格号、来源、布局及哈希，**无需重新生成旧24张PNG**。新图集必须提供source记录；重排或改名的旧格子必须重新提供生成源。没有该参数时需要整套source记录。`--available` 是批量生成期间的临时打包模式，不用于正式发布。

脚本先试无损，再试质量90/85/80/75，必要时按格缩小；增加8%透明边距，保留alpha，不做逐姿态紧裁剪。输出文件名含SHA-256；更新 `skill-art.json` 与最终提示词记录。新文件cdn暂为null，必须完成下一步后才算可发布。

## 5. 上传并核验

使用Maisi的 `upload-deploy-cdn-files` 技能及现有安全配置，不在代码、提示词或日志中写凭据。当前正式对象目录是：

```text
keepwork/haqi-adventure/skill-atlases/skill-atlases/<文件名>.webp
```

注意上传器传入目录时会再附加目录名。首次整目录上传曾使用前缀 `keepwork/haqi-adventure/skill-atlases/` 加本地 `skill-atlases` 目录，因此目前有两级同名目录；不是猜测地址。

新增时只上传本次新文件，用文件路径参数和完整目标前缀：

```powershell
python <maisi>/.github/skills/upload-deploy-cdn-files/qiniu_upload_local_files.py --prefix keepwork/haqi-adventure/skill-atlases/skill-atlases/ <新WebP文件路径>
python scripts/verify_skill_art_cdn.py
```

用上传器实际返回的URL核对。校验脚本逐张检查HTTP200、CORS、字节数、SHA-256、RGBA尺寸及每个使用格子的透明边缘，全部成功才写CDN URL。改变目录时必须同步调整核验脚本，不能手工填入未上传的地址。额外同步digitalhuman-resource镜像遵循上传技能的单独确认要求。

## 6. 配置施法、粒子和附加效果

在 `spell-effects.json` 的bases中配置演出，cards只引用base和variant。图集通过同一base连接，不额外复制到效果代码里。`duration` 是展示时长；`count` 控制粒子预算，`scale` 控制大小；`friendly`/`area` 表示目标关系及群体展示，`secondary` 保留附加效果。

| 描述语义 | kind（或召唤attack） | 程序层 |
|---|---|---|
| 冰剑、连续刃击 | swords | 分批齐射、曲线拖尾、冰屑命中 |
| 冰石、火石坠落 | meteor | 加速下坠、雾/余烬拖尾、落地多环与碎块 |
| 电击、旋风 | lightning / vortex | 分叉闪电、螺旋风带、飞散晶片 |
| 藤蔓、束缚 | vines | 自地面生长的曲线藤蔓 |
| 治疗、护盾、增益刃、陷阱 | heal / shield / blade / trap | 升起光点、屏障轮廓、环绕刃、地面尖刺 |
| 吸血 | drain | 命中后粒子向施法者回流 |
| 吸收、反射 | absorb / reflect | 椭圆护罩、蜂窝纹、折返轨迹 |
| 净化、偷取、眩晕、冻结 | cleanse / steal / stun / freeze | 消散弧线、回收流、头顶星、冰棱 |
| 场地、魔力、隐身、宠物等 | aura / pips / stealth / pet 等 | 使用对应显式辅助演出，见EFFECT_KINDS |

角色召唤 `kind: summon` 还要配置 `attack`，例如海狮主体搭配swords，火魔搭配meteor。生成角色不能代替其攻击粒子。DOT、净化、吸收、眩晕等附加语义保留在secondary，命中后叠加。群体通过targets重复目标演出，不重复播放整套声音。

`spell_effects.js` 的顺序为：地面法阵 → 图集主体 → 五系粒子 → 类型攻击/辅助轨迹 → 命中与余效。**图集绘制成功后不要提前return**，否则会再次丢失粒子层。失败施法跳过正常主体/攻击；减少动态模式保持静态提示，不播放运动粒子。

五系粒子分别为冰晶/寒雾、上升火星、细电弧、叶片/生命光点、幽魂弧线；视觉随机数独立播种，禁止调用Math.random或消耗战斗RNG。新增图形放展示模块，不放战斗core。每种新粒子都须在正反方向、群体和小屏尺寸下检查。

## 7. 配置音效

当前音效为原生Web Audio合成，无外部音频下载，也不声称是原版录音。`spell_sound_core.js` 按学系、kind、召唤attack和时间轴返回cue；`spell_sound.js` 管理用户手势解锁、包络、滤波噪声、音量、声部限制和停止。

- 寒冰使用高频晶体音，烈火使用低频及噪声，风暴使用锯齿/噪声，生命使用上行铃音，死亡使用低沉滑音。
- cue的at是0–1归一化时间，复用释放/命中节点。音高、duration、gain、noise只影响音效，不影响战斗。
- 九帧角色并不意味着每帧发声；冰剑可按齐射分声，治疗有上行余音，吸血有回流音。
- 当前每声短于1秒、总输出增益0.3、最多24个活动声源。暂停、手动定位、换卡、后台、关闭音效会停止；恢复不补播错过的声音。
- 冒险默认请求开启，预览默认关闭；二者共用本机音效偏好，与背景音乐/云端存档独立。浏览器必须先有用户手势才会发声。

后续引入录制音频时，先确认使用权，上传永久Keepwork CDN，登记来源、哈希、时长与音量，仍保留同一解锁/静音/停止机制，避免在draw()每帧播放。

## 8. 验收与提交

```powershell
npm run audit:effects
npm test
```

- `HaqiCards.html?assets=local` 与 `?assets=cdn`：逐格核对原画、名字、费用及变体；透明无底色、无串格，文字不被遮挡。
- `HaqiEffects.html`：检查蓄力/释放/命中/余效，单体/群体/反向，低费/高费，附加效果和失败状态；主体与粒子都应清楚。
- 开关音效、暂停、重播、拖动进度、切后台，检查无叠音、无补播、声画同步和实际听感；检查减少动态模式。
- `Haqi.html` 实战检查手牌、配卡与真实目标演出；完成一场战斗。数值规则不应随演出变化。
- 新增base后更新覆盖数测试和审计文档；不能只改计数让失败消失。追加 `docs/devlog/devlog_YYYY-MM-DD.md` 和QA记录，保存提示词、清单和WebP。
- 浏览器/声音设备不可用时，明确写出未完成的视觉或试听项，不把Canvas命令测试当作观感验收。

按本仓库约定提交并推送main。纯前端无需构建；生成工具、Python依赖与原PNG只用于开发，运行时只使用已提交清单/WebP及永久CDN。
