# 战斗回归验证

## 日常：快速脚本

每次战斗相关修改完成后执行 `npm run test:battle`。仅运行 Node 测试，不启动浏览器、不访问 CDN、不构建、不操作玩家存档。失败返回非零退出码。

`scripts/test_battle_fast.mjs` 按文件名前缀收录测试；新增战斗测试优先使用 `battle_*.test.mjs`，其他命名需同步收录规则。不要通过删除失败用例或缩小收录范围制造通过。

当前覆盖：公式、引擎与确定性、PVE 与回放、AI、红蘑菇阵容及匹配难度、准备与选牌时钟、目标合法性、手牌/符文、宠物/坐骑、状态与提示交互、法术表现与音效逻辑、副本/野外战斗及奖励持久化。覆盖来自实际行为测试；不代表浏览器布局与声音播放已经验收。

### 点击目标回归

旧的 Canvas 点击逻辑依赖脚底距离；骑乘人物的上半身远离脚底，可能更接近另一角色的脚底，导致选错目标、随后被合法性检查拒绝。缩放后的事件坐标也必须与画布 CSS 坐标统一。这是代码中可复现的失败路径，不能仅凭截图断言当时每个失效事件都源于同一个原因。

生产渲染器通过 `battleTargetRects` 生成含人物/坐骑范围的点击区域，生产 UI 通过 `bindBattleTargeting` 统一坐标。`battle_targeting_integration.test.mjs` 直接执行这两个生产模块，再接真实目标校验与 PVE 引擎：错误目标不推进回合，点击骑乘上半身选中自己并产生增益，随后点击敌人造成伤害。覆盖 75%、100%、125%、200% 的边界缩放和两档场景缩放，以及零尺寸画布。用例明确验证旧的脚底算法在同一点选错目标。

Node 中的画布使用最小事件适配器；不能检测真实 DOM 遮挡、CSS 层叠、资源解码或音频设备问题，这些留给发布前浏览器验证。

## 发布前：haqi-release-qa Skill

个人技能升级为 `~/.codex/skills/haqi-release-qa/SKILL.md`，旧名保留兼容入口。提供简单、核心、全部三档产品黑盒测试，见 [整体发布前 QA](product-release-qa.md)。普通修改继续使用快速脚本。下列为完整战斗专题清单，执行时按所选档位抽样，不要求简单档跑完整清单。

1. 阅读当前 AGENTS、此文档、QA 记录和变更。执行快速回归、`npm test`、`npm run build`；保存真实退出状态，不发布。
2. 用本地 HTTP 服务提供构建产物验证正式入口。测试夹具需另外提供仓库静态服务，不依赖它们存在于 dist。用独立来源/访客存档，不改现有玩家数据。
3. 读取可用 computer-use 技能，使用真实浏览器输入，检查桌面、窄屏及缩放。选择卡牌后实际点角色/坐骑/名字/面板，不能直接调用 target 回调代替交互。
4. 覆盖无坐骑/有坐骑 PVE、PVE 组队、红蘑菇 1–4 人模式；攻击、自身增益、友方治疗、错误目标、重选、弃牌、跳过、动画期间输入锁定、胜负结算与撤退。
5. 红蘑菇检查 3–5 秒对手依次加入、人齐后才开始 15 秒准备、点击准备与自动进入真实战场、每轮选牌超时跳过、最后 5 秒音效及静音、倒计时中央偏上、对手人宠比例/坐骑、名字系别图标、战绩只结算一次。
6. 检查骑乘 buff 图标不盖人物；状态提示点击不能施法；完整打完模拟器 1v1，批量页五系各 200 场能出矩阵。验证战绩刷新后保留、任务进度和战斗恢复。
7. 现有隔离夹具：`tests/fixtures/battle-targeting.html`（骑乘点选与真实施法）、`tests/fixtures/battle-status.html?mounted=1`（状态位置）。夹具不是完整游戏入口的替代。需要确定性失败场景时新增只在测试目录的夹具，不给正式产品添加作弊入口。
8. 在 `docs/qa-report.md` 与当日 `docs/devlog/` 记录命令、用例、视口、通过/失败/未验证及失败证据。无法运行的项目标注未验证，不能推断通过。修复后重跑相关快速测试和失败浏览器路径。
