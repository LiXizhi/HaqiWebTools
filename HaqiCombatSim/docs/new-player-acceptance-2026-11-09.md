# 新手搭档样板：实测结果与两天分工

日期：2026-11-09
状态：内部修改与验收任务，尚未通过正式发布验收。

## 本轮目标
保留《失落的光》、建角及营地落点。小屋作为后续自由玩法入口，不在建角后强制进入。用“发现受困的小家伙—主动帮忙—获得伙伴—看到伙伴发挥作用—有下一件想做的事”验证新手体验。

本轮只证明一段流程能否成立，不承诺已经解决前30分钟留存。英语是帮助角色达成目的的工具；不以多邻国题目数量或货币数量作为趣味指标。

## 真实浏览器实测
测试版本：ea6d4e35d13c44fb，Edge，本地访客角色“搭档试玩”。从已创建的角色继续进入，未重测本轮序章和建角。

已实际完成：
1. 进入营地后显示“帮咕噜噜找到朋友”和青龙目标。
2. 点击“前往”寻路，自动打开青龙对话。
3. 接任务后目标切换到莫尼，第二次寻路打开正确对话。
4. 选择英语分支。输入 hello 被拒绝并给出提示；输入 We're friends! 正常通过。
5. 选择“让咕噜噜一起上场”，获得伙伴并更新目标。
6. 点击“去试试新搭档”，实际进入寒冰侦察兵战斗，我方队伍确实包含咕噜噜。
7. 使用火焰爆，对敌方施法，一回合获胜，领取后奇豆变为25。
8. 战后同时出现字源岛推荐及青龙任务，方向不清，已在本地修正营地HUD及世界目标的推荐投影。
9. 刷新后角色仍在角色列表。再次进入并查看宠物时浏览器连接超时，因此完整刷新后伙伴持久化尚未完成浏览器确认；代码级存档测试已通过。

当前仍需解决：
- 英语段主要是看对话及输入一句示范，实际解围没有现场演出。
- 救助前缺少让玩家自己看见、接近咕噜噜的过程；文字说它受困，缺乏画面证据。
- 伙伴展示战一张牌就能结束，没来得及理解伙伴的价值。
- 新伙伴与原抱抱龙的关系要清楚；本场队伍状态只显示玩家及咕噜噜，需核对抱抱龙的世界跟随身份与战斗身份，不能用对白承诺三者均参战。
- 只测通了一个任务闭环，不能把它叫作完整前30分钟验收。

## 谭雯文：范围与最终验收
负责决定本轮体验要解决的具体问题、冻结文案及奖励用途、合并问题和验收结论。

本轮冻结：
- 起点仍为序章后进入营地；家园在菜单保留。
- 第一目标是结识并获得能使用的伙伴。
- 首次获得的奖励先展示实际用途，再展示数值。
- 伙伴任务结束后有一个明确的下一目标，营地内不同时推荐跨岛中文任务。
- 两天只打磨这一个闭环；不扩商城、订阅、更多学科、更多岛屿。

验收以玩家实际看见的行为为准：能说清眼下要帮助谁、为何行动、伙伴帮了什么、接下来想做什么。卡顿、输入失败、伙伴未入队、重复发奖和存档丢失均必须修复。

完成标准：两路线可走通；奖励只发一次；伙伴能出战；中断后可继续；下一目标唯一且可追踪。尚未完成的明确标出，不用“已优化”笼统带过。

## 彬彬：现场反馈、伙伴展示和操作引导

负责文件：js/view_opening_journey.js、view_adventure.js 中该任务HUD、相关场景渲染与共享样式。复用现有咕噜噜、抱抱龙及场景美术，不另起一个独立小游戏。

第一天交付：
1. 列出现有可复用角色、动作、音效和场景事件；没有资源的动作先用现有移动、朝向、表情及气泡组合，不把文案当成已实现动画。
2. 接任务后让玩家看见目标小家伙或清楚的场景指向；到场后才进入解释或挑战。
3. 输入成功后，至少有可观察的场景变化，例如小家伙靠近玩家、目标解除、跟随出现；具体实现依据已有事件与碰撞规则。
4. 领取伙伴后清楚显示名字和用途，并提供一个主按钮去试用。区分原抱抱龙与新伙伴，避免承诺未实现的行为。
5. 优化英语输入页：主任务突出，示范和提示可用，错误提示靠近输入框，不把全部分支按钮重复堆在输入框下。

第二天交付：
1. 与伟强一起设计一次能看清伙伴出手或帮助的短展示。先核对现有AI与动作，优先复用已有伙伴机制；不要单纯加血拖长战斗，也不伪造玩家已经施法。
2. 玩家保留选牌、选目标及取消能力；必要时分步提示“选卡—选目标—确认”。
3. 核对桌面及窄屏下文字、输入框、主按钮、关闭按钮均可见可点。
4. 交首遇、输入反馈、伙伴加入、伙伴战斗、战后下一目标五个状态的截图或短录屏。
5. 本人至少完整走一遍闭环，写出最无聊的一段及实际改法。

完成标准：玩家能看见帮助前后的变化；能认出奖励伙伴；能观察伙伴在下一场做了什么；关闭窗口后还能找到当前目标；不增加新的强制长动画。
