# 汉字互动故事制作指南

本目录存放面向儿童的汉字互动故事页。每个故事把字形、字义、声音和动作编成一段可以亲自参与的短动画；它不是把一个汉字贴在普通网页上的装饰。用户可从 [hanzi_index.html](./hanzi_index.html) 进入正式故事，`obsoleted/` 仅保留历史页面，不发布。

当前正式页面：门、休、森、光、国、雨、明、武。在线入口：<https://cdn.keepwork.com/keepwork/cdn/hanzi/hanzi_index.html>。

> **父页面通信与多语言硬性协议（Haqi H5 Protocol v1）**：所有汉字动画必须同时支持独立运行（外网多产品复用）与通过 `window.parent.postMessage` 嵌入游戏内的字源岛任务和汉字字典（支持 `ready`、`init`、`translate`、`written` 书写完成、`completed` 尾声完成，以及**仅字幕双语同显、常用 UI 按 `displayLanguage` 单语翻译**）。详细协议约束见 [AGENTS.md](./AGENTS.md) 与 [../docs/hanzi-animation-protocol.md](../docs/hanzi-animation-protocol.md)。

## 先定故事，再定技术

- 核对汉字的读音、含义、部件和笔顺。真实字源、教学约定和艺术化想象要分清；画面隐喻不能冒充文字学事实。
- 用一句话写清本字的情感和动作主题，再安排「引子 → 探索 → 变化 → 成字 → 亲手写字 → 余韵」六段分镜。每一段都让孩子看见或完成一个变化，避免连续播放很久却没有参与点。
- 让物件、人物和动作逐步组成字的结构。成字转场应当是故事的结果，不能在最后突然叠上一张汉字图片。
- 页面标题、拼音、提示、旁白和结尾都服务于同一个字。用户可见文案使用简短、自然的中文，不堆百科知识，不使用 emoji。
- 先画出桌面宽屏和手机竖屏的构图草图，再选择 Canvas 2D 或 3D。技术应服务于字形和叙事；简单、清楚的 2D 比勉强加入 3D 更合适。

## 2D 动画指南

[hanzi_guang.html](./hanzi_guang.html) 是 Canvas 2D 参考：它用明暗转场、平面绘本、笔墨层和视差构图把观察、互动和描写串在一起。

- 为每个字建立独立的色彩、光源、材质和构图语言。背景、主体、笔画和提示要有清楚的前后层级，缩小到手机宽度仍能认出关键形状。
- 用少量高质量关键帧、缓入缓出、粒子或笔墨拖尾表达变化；动作应有起点、过程和落点。避免持续闪烁、过度弹跳和与字义无关的特效。
- 用 Canvas 的设备像素比适配高密度屏幕，重绘时按当前视口重新计算安全区域、相机边界和命中区域。不要只把桌面画面整体缩小。
- 需要描字时，显示正确笔顺、起止点和可见轨迹。拖动过程中给出即时反馈，偏离时允许温和纠正或重试，不要因一次失误卡死故事。
- 把角色、道具、字幕和控制条分层绘制或放在 DOM 中，确保文本清晰、按钮可访问、画面变化不会遮住教学信息。

## 3D 动画指南

[hanzi_sen.html](./hanzi_sen.html) 是 Three.js 参考：它用树林的空间纵深承接字义，并以 2D 墨迹层、标题和字幕保持叙事清楚。

- 只有当空间、景深、环绕或镜头运动能解释字义时才使用 3D。模型数量、材质和灯光保持克制，让字形和互动成为视觉焦点。
- 规划固定的镜头段落：建立环境、聚焦部件、完成组合、回到可书写的汉字。镜头运动必须可暂停、可跳过，并在竖屏中保持主体和笔画完整可见。
- 提供 WebGL 不可用、初始化失败或低性能设备的 2D 回退；回退后仍可完成所有故事步骤和描字任务。不要把 WebGL 失败当成空白页。
- Three.js 必须使用已核验的 Keepwork CDN ES module：`https://cdn.keepwork.com/keepwork/cdn/vendor/three/three.module.js`。新增库、后处理或字体资源也必须先核对项目登记的 Keepwork CDN，不得从其他公共 CDN 引入。
- 在移动端限制像素比、阴影、后处理和同时可见的对象数量；页面切到后台时暂停渲染循环，恢复时继续当前进度。

## 互动、声音与字幕

- 至少设计一个真正推动故事的操作，例如点击点火、拖动开门、长按生长、旋转观察或按笔顺描字。操作应在一秒内产生可见反馈，并改变场景或推进分镜。
- 同一动作支持触控、鼠标和键盘。触控目标保持足够大小并留出间距；按钮有明确的中文名称、焦点样式和 Enter/Space 操作。处理拖动取消、窗口失焦、重播中断、屏幕旋转和重复点击。
- 开场提供「开始」或「播放」按钮，由用户手势启动音频。声音只做增强，不能成为唯一线索；提供全局静音/恢复声音控制，静音后仍可完成全部操作。
- 为每个关键动作配一层简洁的声音反馈：轻触、拖动、完成、错误和成字可以有不同质感。避免连续高音、突然的大音量和未经许可的长背景音乐；音效文件按需加载，失败时不阻断故事。
- 字幕和旁白同步到动作的关键节点，而不是把整段说明一次性铺满屏幕。字幕使用高对比度底板或描边，留在安全区域内；提供暂停后仍可阅读的停留时间，以及「重播旁白」或重新播放当前段落的入口。
- 视觉反馈、声音、字幕和震动（如使用）应互相独立。尊重 `prefers-reduced-motion`、系统静音和辅助技术设置，减少动态时保留关键状态和可操作结果。

## 响应式与可访问性

- 桌面宽屏、平板、手机竖屏和手机横屏都必须完整显示主角、笔画、提示、字幕、按钮和触控目标。按视口重新布局，不得靠裁切、遮挡或把内容移出视口来适配。
- 使用 `env(safe-area-inset-*)` 处理刘海和底部手势区；文字、按钮和笔画在高像素密度屏幕仍应清楚。横竖屏切换后保留当前分镜、互动状态和静音状态。
- 颜色不能是唯一提示方式；错误、完成和可操作区域同时用形状、文字、动画或声音表达。键盘用户可依次访问所有控制，焦点不被 Canvas 或全屏层吞掉。
- 首屏应快速可用，故事资源分段加载。动画循环只在需要时运行，监听 `visibilitychange` 暂停后台工作；清理计时器、事件监听器和 WebGL 资源，避免重播后性能逐次下降。
- 动画不得引起高频闪烁或晕动风险。为减少动态效果提供稳定的静态构图、淡入淡出和可跳过步骤；错误提示要友好、具体、可恢复。

## 文件与实现约定

- 每个正式故事使用独立的 `hanzi_<拼音>.html`，尽量内联页面专属样式和脚本，保持普通 HTTP 静态服务可直接打开。通用逻辑才抽取为明确的相对路径模块。
- 源码保持原生 HTML、CSS、JavaScript；不得引入 TypeScript、前端框架或未登记的第三方 CDN。资源路径、音频、字体和图片都要有明确的线上地址或可用的本地回退。
- 资源遵守项目的 WebP、透明通道、尺寸和 CDN 规则。需要 Canvas `getImageData()` 的跨域图片，在设置 `src` 前设置正确的 `crossOrigin`，并在发布前验证实际 CDN 的 CORS、解码和裁剪。
- 文案和交互状态集中管理，避免把同一个提示复制到多个事件处理器。重播应重置动画、声音、字幕、描字轨迹和按钮状态，不能刷新页面才能恢复。
- 页面出错时仍显示可理解的中文错误或回退内容；控制台不得有未处理异常、资源 404 或音频自动播放错误。

## 新增或更新故事的流程

1. 在本目录编写或更新 `hanzi_<拼音>.html`，完成故事分镜、2D/3D 动画、互动、声音、字幕和回退路径。
2. 在 [hanzi_index.html](./hanzi_index.html) 的 `<nav class="list">` 中加入或更新正式入口，使用 `https://cdn.keepwork.com/keepwork/cdn/hanzi/hanzi_<拼音>.html`。索引应覆盖所有正式 `hanzi_*.html`，不包含 `obsoleted/`。
3. 用本地 HTTP 静态服务验证：从开场走到成字和描写，再完成重播；检查桌面宽屏、手机竖屏、手机横屏、缩放、触控、鼠标、键盘、静音、字幕、减少动态效果和 WebGL 失败回退。
4. 检查浏览器控制台、网络请求、音频解锁、资源尺寸、CDN CORS 和实际加载速度。不要以「能打开首屏」作为完成标准。
5. 先上传改动的故事，确认成功后最后上传索引。使用仓库已登记的 `upload-deploy-cdn-files` 技能及七牛脚本，从 HaqiCombatSim 根目录执行；不要运行会发布整个游戏的 `npm run upload`，不要把凭据写进命令、源码或日志。

示例：

```powershell
node C:\lxzsrc\keepworksdk\scripts\qiniuUploadLocalFiles.mjs --prefix keepwork/cdn/hanzi/ .\hanzi\hanzi_xiu.html
node C:\lxzsrc\keepworksdk\scripts\qiniuUploadLocalFiles.mjs --prefix keepwork/cdn/hanzi/ .\hanzi\hanzi_index.html
```

把 `hanzi_xiu.html` 换成实际修改的文件；多个明确文件可在同一次调用中上传，但不要重传无关页面。脚本读取现有 `qiniu.yaml` 凭据并提交 CDN 刷新。上传后核对每个文件的成功记录和刷新结果，再访问实际 CDN 页面与索引逐项点击验证；覆盖同名 URL 后等待缓存刷新，再确认线上内容。

## 发布到 CDN 做线上检查

需要让同事或测试设备检查一个故事时，也按正式 CDN 路径发布，避免只在本地文件协议下验证。线上检查不等于正式上线，索引应在故事页面确认可用后再更新。

1. **准备检查对象**：只上传要检查的 `hanzi_<拼音>.html` 及其明确依赖。确认页面没有把本地绝对路径、临时图片地址、测试 token 或密钥写入源码；相对路径依赖也必须放在同一个 CDN 前缀下，或改用已核验的永久 Keepwork CDN URL。
2. **上传故事页面**：从项目根目录执行上传命令，显式指定 `--prefix keepwork/cdn/hanzi/`。命令结束后记录每个文件的成功、失败、跳过状态、object key、CDN URL 和刷新结果。任何失败或跳过都先修复，不要继续发布索引。
3. **直接检查线上 URL**：打开 `https://cdn.keepwork.com/keepwork/cdn/hanzi/hanzi_<拼音>.html`，不要只检查本地页面。先等待 CDN 刷新完成，再用无痕窗口或清空缓存重新加载；同时用浏览器开发者工具确认 HTML、脚本、图片、音频和 Three.js 依赖没有 404、CORS 错误或旧版本缓存。
4. **走完整体验**：在至少一台桌面设备和一台手机上从开场走到成字、描写、字幕、声音和结尾，再执行重播。检查触控、鼠标、键盘、静音、暂停、横竖屏切换、减少动态效果和 WebGL 失败回退；记录发现的问题和实际 CDN URL，便于复现。
5. **确认后更新索引**：故事页面在线检查通过后，再上传 `hanzi_index.html`。打开线上索引并点击新增或更新的入口，确认它指向刚检查过的 URL；索引上传失败时保留旧索引，不要让用户看到未验证的链接。

线上检查可用以下方式快速确认响应；它只能证明 URL 可访问，不能代替浏览器中的互动验收：

```bash
curl -fsSL -o /dev/null -w '%{http_code} %{url_effective}\n' \
  https://cdn.keepwork.com/keepwork/cdn/hanzi/hanzi_xiu.html
curl -fsSL -o /dev/null -w '%{http_code} %{url_effective}\n' \
  https://cdn.keepwork.com/keepwork/cdn/hanzi/hanzi_index.html
```

如果同名 URL 仍显示旧内容，先核对上传输出中的 object key 和刷新结果，再等待 CDN 缓存刷新；不要通过改文件名或添加未登记的临时 CDN 域名绕过验证。

## URL 规则

前缀固定为 `keepwork/cdn/hanzi/`，文件名就是 URL 最后一段。独立文件模式不会自动带上本地 `hanzi/` 目录，因此必须显式使用 `--prefix`。CDN 不会自动发现新文件；新增故事必须先更新并重新上传索引。
