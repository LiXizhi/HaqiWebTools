## RSI 接入现状与未来流程

本次只读取了 apps 仓库 `.github/skills/ris/SKILL.md` 和 `targets.json`。检查时登记表只有 `school-teacher`，没有 Haqi 语言课程目标。**不能直接运行该目标并把课堂技能的通过结果当作游戏课程验收。** 拟议目标名为 `haqi-language-curriculum`，尚未注册；本次不修改 apps 仓库，不启动自动循环或模型请求。

注册时须按所属项目规则设计允许修改的文件范围、版本备份、基线、失败恢复、保留条件。注册前若人工修故事，也只修一个清楚的小目标并保留差异，不绕过已注册工作流的硬门槛。

建议的单轮输入：

```text
目标：EN-U01 的“询问等待地点”，不是笼统“改进所有语言”。
基线：作者源哈希、课程版本、词条来源、现有进度契约、失败用例。
本轮缺陷：孩子知道在找朋友，却不知道为什么要去下一处。
允许修改：一个故事的对白／提示／目标；不自动改奖励或任务身份。
候选：保留原结局，改写线索与问答；说明改变的语言负荷。
验证：来源和自然度、情节、场景事实、独立迁移、旧存档与回执。
输出：保留或拒绝、原因、变更清单、未完成项、下一项建议。
```

硬门槛：不能伪造来源、物品动作或人物移动；不能用提前揭晓答案提高通过率；不能减少困难样本让得分变高；不能放宽回执去重、奖励、旧存档与语言隔离。未见过的验证故事／问题不参与候选生成。

评价维度：剧情可理解、语言自然、难度适宜、四技能覆盖、真实动作、迁移表现。每项必须附证据；“另一个模型给了高分”只能作辅助。技术检查全过但读者仍不明白故事时，教学状态仍不能通过。

每轮报告建议写到 `docs/curriculum/reviews/<日期>-<单元>-<轮次>.md`（目录和报告尚未创建）：记录基线与候选、评审人／模型、测试条件、成绩、失败、保留／拒绝、回滚位置和未完成项。实际开发日志仍写 `docs/devlog/`。没有真实语音就注明，没有实测迁移就注明；自动晋级不得越过人为要求的语言和儿童体验评审。

## 验证命令按修改范围选择

- 仅本目录 Markdown：核对链接、单元 ID、语言数、候选与已实现状态及来源；不默认跑构建、发布或战斗测试。
- 修改正式故事：`python -X utf8 scripts/export_story.py`、`python -X utf8 scripts/export_story.py --check`、`python -X utf8 -m unittest discover -s tests -p "story_*test.py"`。
- 修改课程行为：增加针对实际缺陷的行为测试，核对目标词、真实对象、回执、异步取消与旧进度。
- 涉及战斗或共享战斗 UI：必须 `npm run test:battle`。浏览器／真实语音的范围按任务和项目规则另记；发布前再用产品 QA 技能，不把发布流程塞进每轮写作。

不自动提交、推送、发布；RSI 候选保留也不代表获得这些操作的授权。
