## 黑盒判定

### 放映室也纳入产品验收

`HaqiPromo.html` 是持续维护的正式辅助入口，三档均收录：简单约 30 秒启动/播放/跳章冒烟，核心约 3 分钟检查核心镜头、三画幅与整片检查，全部约 10 分钟检查两版本、章节、播放控制、字幕、录屏/全屏和 JSON/SRT 导出。这些时间从原档位预算中分配，不自动延长总时间。

同时记录外层浏览器视口和内层 16:9 / 4:3 / 9:16 画幅；覆盖创建、卡包、战斗、宠物、装备等 UI 的裁切、遮挡和缩放。详细流程在技能 references/promo.md，页面现状见 [promo.md](promo.md)。

宣传舞台由剧本驱动，当前 iframe 禁止直接指针输入；可用页面“运行整片检查”作为辅助证据，但不替代 Haqi.html 的实际点选目标、配卡保存、存档或联网服务验收。脚本测试可执行 `node --test tests/promo.test.mjs tests/promo-deck.test.mjs`，与浏览器结果分开报告。

### 正式用户路径

从正式入口用真实输入操作，以界面、资产/进度前后和刷新恢复作为证据。禁止用直接调用业务函数、修改内部存储、调试面板或测试夹具代替用户路径。已有脱敏 QA 存档可通过正式导入 UI 准备高级条件，但必须记录来源和版本；缺账号、数据或环境标为阻塞。

测试使用隔离访客/已授权测试账号，不覆盖玩家数据。实际付款和公开通信不由运行 QA 自动授权。默认测试产品，交付缺陷；若另有修复授权，修复后用新版本重测并记录。Node 脚本为补充证据，不能代替黑盒验收。

报告保存到 docs/qa-reports/qa_YYYY-MM-DD_HH-mm_<scope>.md，证据放对应子目录，docs/qa-report.md 追加索引。每项列通过/失败/阻塞/未执行/不适用，注明版本、实际耗时、视口、复现与缺陷等级。简单档只给冒烟结论；关键项没测或失败不得称全产品验收通过。

日常代码修改规则不变：战斗相关修改运行 `npm run test:battle`，不自动触发慢速黑盒 QA。本次仅升级技能与文档，没有执行上述 10/30/90 分钟验收；耗时是预算目标，尚非实测性能。
