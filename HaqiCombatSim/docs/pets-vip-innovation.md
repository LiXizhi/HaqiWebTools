# 计划需求：帕鲁式宠物创新与 VIP 口粮 / 治疗

> 状态：**计划中，尚未实现。**  
> 来源：产品负责人李西峙，2026-09-18 钉钉私信 Lily（未改产品 git；草稿备忘仅作意图，不以草稿原文为规格）。  
> 范围：在现有冒险宠物上，朝《帕鲁世界》（Palworld）方向做伙伴创新；治疗 / 宠物口粮可以与 VIP 挂钩。不另造付费网关。

本文对照 [pets-and-shop.md](pets-and-shop.md) 与相关代码，区分**已经能玩的**和**产品尚未拍板的**。不虚构 VIP / 商店生产接口。

## 目标

- **帕鲁式创新**：宠物不只是卡组里的附属牌，而是可捕获、可编队出战、要照顾、能成长的伙伴。产品原话是「类似帕鲁世界去创新宠物」，没有写成功能清单。
- **治疗 / 口粮与 VIP**：回血或宠物食物可以做成会员门槛，或至少与会员档位相关。具体锁哪些、锁到什么程度，仓库给不出默认值。

成功标准尚未写成验收清单；在 VIP 身份源与「锁哪些资源」确认前，本需求不进入实现。

## 仓库里已经有什么

2026-09-18 的抱抱龙 / 全宠物 / 50 级商店已经落地，见 [pets-and-shop.md](pets-and-shop.md)。那是网页冒险改编，不是帕鲁世界克隆，也不是原版战宠 1:1。

### 已接近「捕获 + 编队 + 养成」的部分

| 已有能力 | 位置 | 说明 |
|----------|------|------|
| 359 种来源宠物 + 三色初始抱抱龙 | `data/adventure/pets.json`，`scripts/export_pet_catalog.mjs` | 快照自 MagicHaqi `famous-pets/_pet_index.json`；保留 `sourceId`、`dna`、`traits`、四行图集。咕噜噜是教学伙伴，不进 359 图鉴。 |
| 野外捕获 | 抓宠符文 / PvE | 普通、高级、顶级抓宠符文。kids公式：权重 × 损失生命比例 + 等级差/80。成功或失败都消耗一张，优先于伙伴 AI；结束战斗才领取，撤退不领。捕获晶球已停售，未使用的库存换成普通抓宠符文。 |
| 四卡位编队 | `save.formation` / `heroSlot`，`partySpecs` | 同位伙伴跟随，卡包放入主角独立 `petCards` 牌池，通过“使用宠物卡”选择，不占普通手牌名额；另外三格独立自动出牌。每种宠物只收藏一只，重复捕获 +50 宠物经验。 |

| 饱食、营养餐、非战斗回血 | `tickCare`，`BalanceParams.adventure` | 携带宠物在线每分钟 −1 饱食；低于 30 自动吃营养餐，每份 +40。0 饱食暂停回血，不死亡。全体已拥有且不饥饿的宠物每分钟回 5% 最大生命；离线只回血，最多算 24 小时。战斗不走自然恢复。 |

| 教学口粮（另一套） | 章节任务 63009，道具 **17172** | 咕噜噜喂养：每包 +300 经验，满级不再消耗。与 990001 营养餐不是同一物品。 |

PvP 引擎里的 `CatchPet` / `PickPet` 仍登记为 **unsupported**（[architecture.md](architecture.md)），官方 Aggressive 预设也不带这些 key。冒险捕获是独立规则，不要当成原版 `CatchPet` 卡已接通。

### 会员 / VIP：界面有入口，规则没有

| 事实 | 依据 |

| 会员状态 / 付费 | 存档无 `vipLevel` 或等价字段；没有开通、到期、档位。 |

| 本引擎 VIP 战斗加成 | 没有。`baseMaxHp` 注释写明未含 VIP；对照见 [player-import.md](player-import.md)。 |
| 兄弟项目手工 VIP | `HaqiCombatEmulator/` `vipLevel` −1..10，仅 kids 配装模式；不是线上会员，也不是本冒险商店。 |

因此「治疗 / 口粮 VIP 化」目前只有产品意图，没有任何现成开关可打开。

### 明确没有的（相对帕鲁世界常见玩法）

下面这些在本仓库**搜不到实现**，也没有写成规格。列出它们只为避免把现有四卡位养成误读成已经帕鲁化：

- 同一种宠物养多只、劳动编制、据点生产线。
- 繁殖、骑乘、工种技能树。
- 把饥饿 / 回血 / 口粮锁在会员档。
- 付费币、VIP 商店接口、会员开通回调。
- 家园云双向同步（联动格式已有，写入未做）。

现有商店文案已经写明：没有付费购买或另造货币。

## 和《帕鲁世界》的对照（便于讨论，不是规格）

产品只给了方向，没有逐条功能表。用现有系统对照，方便下次拍板时知道「已经像什么、还缺什么」：

| 帕鲁常见要素 | 本仓库现状 | 是否可当已交付 |
|---------------|------------|----------------|
| 野外捕获球 | 普通/高级/顶级抓宠符文，按kids公式 | 已改用符文；捕获晶球停售 |
| 编队出战 | 四卡位，同位独立宠物牌池、其余独立 AI | 已有 |
| 饥饿与喂食 | 饱食 / 营养餐 / 自动进食 | 已有，无 VIP 门 |
| 非战斗回血 | 每分钟 5%，饥饿则停 | 已有，无 VIP 门 |
| 图鉴收集 | 一种一只，重复转经验 | 已有；不是多种劳工 |
| 基地干活 | 无 | 未做，也未否决 |
| 会员锁粮 / 锁治疗 | 无 | 产品点名，未设计 |

「创新」可以落在现有捕获/编队/养成上加深，也可以新开劳动/据点层。代码无法替产品选。

## 开放问题（代码无法回答）

下面在仓库里找不到依据。**未确认前不得编造 VIP 接口、支付或商店合约。**

### 1. 帕鲁化做到哪一层

- 本期是把现有 359 种伙伴的捕获 / 编队 / 饱食做深，还是要上据点劳动、繁殖、骑乘？
- 一种一只的收藏规则是否保留？帕鲁式劳工通常需要同种多只。
- 战斗伙伴与「家园 / 据点工人」是同一只宠物，还是两套成长？`exportPetLink` 已把冒险等级与家园成长时间分开，但家园写入未做。
- 与 MagicHaqi 家园的关系：只继续版本 1 导出，还是要双向？AGENTS.md 禁止把 SDK token 写入存档。

### 2. VIP 锁哪些、怎么验会员

- 锁的是：章节口粮 17172、营养餐 990001、自然回血、捕获晶球、商店宠物，还是会员专属粮？
- 「可以 VIP 化」是：非会员买不到 / 买得到但效果差 / 非会员限次数 / 仅会员自动进食？
- 会员身份从哪来：本页「升级会员」（现在是空按钮）、Keepwork 账号、原版魔法哈奇 VIP，还是 [player-import.md](player-import.md) 将来导入的 `vipLevel`？三者目前互不相通。
- 没有身份源时，本地冒险能否继续免费喂食？失败不得阻断现有单机养成。

### 3. 支付与商店

- 全仓库没有 VIP 开通 URL、商品 ID、回调或凭据。奇豆是冒险内货币，不是支付渠道。
- 是否允许用奇豆买「会员粮」、用真钱买会员、或两者都不要、只做档位开关？
- kids 与 teen、模拟器对战页（排除 Pet key）是否纳入本期？对战预设仍过滤 `/Pet|...|VIP/`。

### 4. 数值与公平

- 会员粮是否改变饱食 / 回血公式，还是只改能否购买？现参数在 `BalanceParams.adventure`（`hungerPerMinute`、`foodRestore`、`regenPerMinute`、`foodPrice`）。
- 异步 PVP / 真实号导入后，会员回血或会员粮会不会变成付费战力？公平竞技 `params.fairPlay` 已有，是否对会员宠物启用未说明。

## 建议的落地顺序（非实现承诺）

1. 产品先定：帕鲁化是「加深现有捕获/编队/养成」，还是要新开劳动/据点；VIP 锁的是粮、治疗，还是两者。
2. 会员身份与 [player-import.md](player-import.md) 共用同一来源；没有身份时本地奇豆商店保持可玩。
3. 若只锁商店：在 `petAction` 的 `buy` / `pet-feed` 与 `tickCare` 自动进食处加档位检查——**等身份字段进存档后再写**，不要先做假 VIP。
4. 据点劳动、繁殖、同种多只若需要，另开规格，不要 silently 改「一种一只」存档语义。
5. 禁止把支付密钥或 VIP 网关写进客户端。

相关计划入口见 [plan.md](plan.md)「计划需求」；现有宠物规则见 [pets-and-shop.md](pets-and-shop.md)；会员战斗数值见 [player-import.md](player-import.md)。

## 2026-09-21 实施更新：商城VIP门槛

用户已明确会员身份来源为Keepwork；商城VIP专属商品的购买门槛现已实现，详见 `pets-and-shop.md` 的 Keepwork VIP 商品购买章节。HUD、会员窗口和购买控制器共用SDK当前账号的内存状态，不保存可编辑VIP字段。普通VIP和SVIP均有效，购买时远端刷新，网络失败不放行。

上文“会员入口无状态”“身份源未明确”“等身份字段进存档”属于2026-09-18历史计划，已被本更新取代。会员身份不应进入角色存档。口粮、治疗、VIP战斗加成、会员支付与家园联动仍未纳入本次范围。

### 魔法星（2026-09-21 更新）

- 本地 `magic-star.json` 来自 `CombatMagicStarPage.lua` 的 `SpecialList`、`ExList`、`NeedInfo`。五件法杖为 1290、1291、1292、1296、1297；后两件需星级 6/10，1291/1292 需角色 21/31 级。
- 用户指定的新规则取代原版 M 值：会员剩余日历月数向上取整、最高 10 级；月末按目标月最后一天截断。非会员/到期为 0 级，已确认会员但无有效日期为 1 级。普通 VIP/SVIP 取有效资格中较晚的截止时间。
- 开放实际领取：每角色每件法杖一次；每角色每周仙豆一次（北京时间周一零点刷新），数量采用原版界面 `SpecialList.weekly_money`。这是本地改编规则，不声称重演原版服务器 ExtendedCost 1658 的发放逻辑。已有法杖不重复发放。
- 每次领取重新查询账号资格，经控制器传入纯规则层；领取记录 `magicStarClaims` 随角色本地/云端存档保存，会员资格本身不写入存档。此为纯前端单机存档约束，不提供跨存档回滚的服务端防刷保证。
- 原版属性加成、魔法口袋随机礼物及环绕外观仅说明尚未开放。商城会员购买限制照旧。“成为VIP”打开 SDK 个人资料，未创建独立付费流程。

### 奖励领取持久化修复（2026-09-21）
角色和云端存档校验白名单必须保留经校验的可选 `magicStarClaims`、`checkin`，不能仅依赖新建角色的初始字段。领取采用暂存后持久化成功再更新内存及提示的流程；存储失败和其他标签页的版本冲突不发奖。仍按每角色每周/每天重置，不将纯前端存档规则视为服务端反作弊。
