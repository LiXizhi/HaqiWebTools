# 单元、词条与故事作者模板

状态：后续课程内容的设计模板，尚无运行时自动导入器。使用项目 `haqi-story` 技能定位真实作者源；不要把此 Markdown 当作可以直接执行的配置。

## 单元头

| 字段 | 填写方式 |
| --- | --- |
| 教学 ID | 如 `EN-U01`；稳定，不充当运行时存档 ID |
| 语言／Level／岛屿 | 目标语言与界面语言分离；写本项目 Level |
| 能做什么 | “在什么情境，通过什么语言完成什么事”，不能只写“学十个词” |
| 前置能力 | 只列本次需要的表达；缺少时提供短支架，不锁地图 |
| 来源 | `sourceId`＋已核版次／单元／页码／Can-do；未核写待核 |
| 目标词及句型 | 首次、复习、只需理解三类；每回合最多 1—3 个明确练习目标 |
| 语音／文字 | 本语专属发音、识字、拼写／笔写路径 |
| 覆盖故事 | A/B/C/T1/T2/T3，写清复现目标和变化条件 |
| 听说读写证据 | 四项分别填写任务与支持程度，不能只写“有语音” |
| 现状 | 设计、来源核对、语言复审、运行时接入、技术验证、教学验证分别记录 |

## 每篇故事卡

```text
教学故事 ID：EN-U01-A
原运行时 ID：en-hanzi-01（例；复用时不重新分配）
作者源路径／语义选择器：data/adventure/island-language-courses.json / id
人物、实际 NPC ID、地点、可用道具／动作：
人物愿望：
具体困难或误会：
第一条线索：
玩家每一步为什么行动：
结局：发生了什么真实变化？哪些只是未来打算？
首次学习的词／语块及规范 entryId：
必须已知的辅助词／需要解释的人名：
哪一处听后做、哪一处读后做、哪一处自己说、哪一处自己写：
家园后续与文字卡复现：
迁移版本：只改变哪些条件？保留哪个交流目标？
尚不支持的玩法：明确列出，不在台词里假装已完成。
```

## 场景分镜表

| 场景 | 人物已知信息／线索来源 | NPC 真正说的话 | 玩家表达意图及示例 | 实际动作／校验 | 后续信息与目标 |
| --- | --- | --- | --- | --- | --- |
| 1 | 尚不知道朋友去了哪里 | 只写人物自己的话 | 先认识对方，不用词汇题开场 | 靠近正确 NPC；示例回答不是自由表达验证 | 得知应该问谁 |
| 2 | 上一场得到方向 | 人物／玩家内心／系统说明分开 | 为找人而问位置 | 路线与对象真实存在；不能凭读词宣布找到了人 | 取得下一条线索 |
| … | 每场只依据此前信息 | 不提前揭晓战后、送信或交付结果 | 问句与回应必须自然呼应 | 战斗、物品动作和语言回答分开校验 | 最后收束人物的原始愿望 |

NPC 描述、任务目标、操作提示不属于对白；它们放到手记或提示字段。非中文语言不能用中文语序直译，韩日语尤其需要核对语体、活用和语境。简单语言不等于去掉所有上下文，更不等于让每个人依次说一个名词。

## 检查清单

- [ ] 孩子知道人物想要什么、玩家为什么需要帮忙。
- [ ] 每一步给出足够的下一步线索，不靠任务面板突然发布无缘由的新目标。
- [ ] 问句、玩家答案、人物回应在语义上连贯；译文完整而准确。
- [ ] 词条来源、规范身份、词义、首次与后续复现可追溯。
- [ ] 实际地图、NPC、动作、战斗和存档身份已核实。
- [ ] 所有新增能力和数据字段标清已实现或待实现。
- [ ] 读写、无原文听力、无答案回应与带提示练习分别验收。
- [ ] 桌面／手机、关闭、重入、语言切换、回执去重、旧进度测试覆盖。
- [ ] 合格语言复审完成；真人体验若未做则明确标注。

示例完整设计见[英文字源岛首章](../story/drafts/en-hanzi-find-friend.md)。该例已经有故事因果和运行时接线，但尚缺本模板要求的完整教学来源对齐、独立读写与迁移测评，不将它当作已满足全部标准的课程。
